# Kernel Admin

[English](README.md) · [فارسی](README.fa.md)

Kernel Admin یک برنامهٔ مستقل React/Vite با Ant Design/antd-style، React Router و Axios است. مرحلهٔ application-verification نقطهٔ ورود، مسیرهای ترکیب‌شده، آداپترهای HTTP محلی، کاتالوگ کامل هر ده زبان و بررسی کامل برنامه را می‌پذیرد. [سیاست دقیق انتشار](.github/bootstrap-policy.json) و [فهرست مرجع بررسی‌ها](.agents/validation.json) را بخوانید؛ اعلام آمادگی جای اجرای واقعی روی نسخهٔ جاری را نمی‌گیرد.

راه‌اندازی برنامه متعلق به [src/main.tsx](src/main.tsx)، [App](src/app/App.tsx) و [Routes](src/app/Routes.tsx) است. هر ویژگی مالک صفحه‌ها، انواع HTTP و endpointهای خود است. مالکیت HTTP و نشست مشترک در src/shared/api و واژگان خالص DTO در src/shared/contracts می‌ماند. API مستقل مالک اجرای احراز هویت، مجوزدهی، پایگاه داده، migration و ذخیره‌سازی است. وابستگی سورس به checkout دیگر، workspace، SDK بک‌اند یا بستهٔ محلی اضافه نشده است.

API مالک زبان فعال، جهت، تقویم و نام‌هاست. پنل راه‌اندازی اولیهٔ ثابت فارسی و تلاش دوبارهٔ صریح هنگام نبود تنظیمات را حفظ می‌کند. فقط پوسته و حالت فشرده ترجیح بازدیدکننده‌اند. هر ده کاتالوگ محلی با interpolation یکسان کامل می‌مانند؛ تغییر زبان فعال به مجوز super-admin در API نیاز دارد.

نسخهٔ Node در [.nvmrc](.nvmrc) و npm همراه آن را به کار ببرید. npm ci، npm run browser:install و npm run validate -- full را در خروجی مستقل از درخت دقیق پیشنهادی اجرا کنید. آزمون سورس فقط از مقادیر عمومی ساختگی صریح استفاده می‌کند و به محیط واقعی، کلید، پایگاه داده، آپلود یا سرویس production نیاز ندارد. فهرست مرجع مالک تمام فرمان‌ها و ترتیب آن‌هاست.

پروفایل کامل برنامه همهٔ بررسی‌های قبلی را حفظ می‌کند و تحلیل کد بلااستفاده، ساخت production، بودجهٔ bundle، قرارداد مصرف‌کننده، مسیرهای واقعی مرورگر، مقایسهٔ تصویری و Lighthouse را اضافه می‌کند. fixtureهای مرورگر ساختگی‌اند و درخواست غیرمنتظره را رد می‌کنند. آزمون مصرف‌کنندهٔ Pact تأیید API مستقل نیست. مقایسهٔ تصویری به انطباق محیط و سورس و تأیید انسانی واقعی تصاویر تازه نیاز دارد؛ تصاویر تاریخی تأیید جاری نیستند.

PRهای مجاز به‌صورت Ready for review و با حداکثر ۱۰۰ ورودی تغییر واقعی منتشر می‌شوند. commit، push، درخواست بازبینی، ادغام، تغییر حفاظت راه دور و استقرار همچنان مجوز صریح می‌خواهند. انتشار سورس یا موفقیت آزمون محلی اثبات سرویس مستقر نیست. workflowهای مستقل عملیات همچنان به مرحلهٔ بعد موکول‌اند.

از [مشارکت](CONTRIBUTING.fa.md)، [راهنمای دستیار](.agents/README.md)، [نقشهٔ وظایف](docs/source-navigation.fa.md)، [معماری](docs/architecture.fa.md)، [اعتبارسنجی](docs/validation.fa.md) و [نقشهٔ مستندات](docs/README.fa.md) آغاز کنید. استقرار، بررسی مقصد و سازگاری API-provider مجوز و شواهد واقعی جداگانه لازم دارند.
