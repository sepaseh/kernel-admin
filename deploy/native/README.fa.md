# پیش‌نیازهای میزبانی بومی

[English](README.md) · [فارسی](README.fa.md)

الگوهای منتشرشدهٔ Nginx و ابزار تولید تنظیمات، مقدمات میزبانی ایستا هستند. آن‌ها سرور نصب‌شده، گواهی معتبر یا استقرار اجراشده نیستند. منبع پذیرفته‌شدهٔ ساخت و `applicationReady` را از [سیاست انتشار](../../.github/bootstrap-policy.json) و بررسی الزامی را از [فهرست مرجع](../../.agents/validation.json) بخوانید. تا وقتی آمادگی false است، پیش‌نیازها artifact برنامه را اثبات نمی‌کنند؛ اعلام true نیز مجوز مقصد اپراتور یا شاهد استقرار نیست.

الگوی کامل برای ارائهٔ پوشهٔ عمومیِ تغییرناپذیر ادمین، API مستقل و originهای عمومیِ مشخص طراحی شده است. الگوی bootstrap فقط برای چالش HTTP مربوط به ACME در عملیات آیندهٔ مجاز است و محتوای برنامه ارائه نمی‌کند. نمونه‌های عمومی ساختگی‌اند؛ تنظیمات واقعی اپراتور یا محتوای گواهی خصوصی را به‌عنوان fixture آزمون استفاده نکنید.

پس از فعال‌سازی برنامه و دریافت مجوز صریح اپراتور، نسخهٔ تغییرناپذیر و سازگار آماده کنید، مقادیر عمومی میزبان و مسیر پایه و شناسهٔ نسخه را تعیین کنید، تنظیمات را در فایل تازه بسازید، گواهی را خصوصی تهیه کنید و تنظیمات Nginx و TLS را بسنجید. سپس نسخهٔ تأییدشده را به‌صورت اتمی فعال و سرویس را reload کنید. تولید تنظیمات فقط نحو و جای‌گذاری مقادیر را بررسی می‌کند؛ DNS، اعتبار گواهی، وجود فایل یا دسترس‌پذیری سرویس را اثبات نمی‌کند.

خطای واقعی برای asset ناموجود، cache تغییرناپذیر فایل‌های hashدار، no-store سند و فرادادهٔ نسخه و originهای صریح CSP را حفظ کنید. میزبان فرانت‌اند نباید پیاده‌سازی API شود. اگر چند سایت روی یک listener مشترک‌اند، virtual hostها را هماهنگ و برای هر آدرس و پورت فقط یک سرور پیش‌فرضِ ردکننده نگه دارید.

[استقرار](../../docs/deployment.fa.md)، [عملیات نسخه](../../docs/release-operations.fa.md) و [بازیابی](../../docs/backup-restore.fa.md) را ببینید.
