# رفتار کلاینت HTTP و نشست

[English](api-client.md) · [فارسی](api-client.fa.md)

client.ts در src/shared/api مالک تنظیم Axios، هویت درخواست، تلاش محدود، لغو و نرمال‌سازی خطا است. token.ts توکن bearer را در حافظه و نسل احراز هویت را نگه می‌دارد. api.ts هر feature قرارداد snake_case را به مدل مصرف‌کننده تبدیل می‌کند. VITE_API_BASE_URL تنظیم عمومی زمان ساخت است.

پاسخ‌های 401 احراز‌شدهٔ هم‌زمان یک refresh مشترک دارند و هر درخواست اصلی حداکثر یک‌بار تکرار می‌شود. خطای درخواست عمومی یا 401 بدون انتساب، مجاز به refresh یا پاک‌کردن ورود فعلی نیست. خروج، refresh و تغییر قدیمی نباید نشست جدید را تغییر دهند. /languages احراز‌شده است؛ فقط خواندن GET/HEAD /settings عمومی است و PUT /settings محافظت‌شده و وابسته به نسل نشست می‌ماند. شکست نهایی refresh کلاینت به معنی ابطال نشست سرور نیست.

خطای گذرای خواندن، سطرهای قبلی را نگه می‌دارد و خطا و تلاش محدود ارائه می‌کند. خواندن لغوشده یا قدیمی نباید حالت جدید را بازنویسی یا حالت خالی اشتباه ایجاد کند. درخواست تغییر داده برای خطای شبکه، timeout، پاسخ ۴۲۹ یا ۵xx خودکار تکرار نمی‌شود. درخواست تغییر محافظت‌شده با نسل معتبر زمان ارسال، اگر لغو نشده باشد، پس از پاسخ ۴۰۱ و نوسازی موفق اعتبارنامه می‌تواند فقط یک‌بار تکرار شود. X-Request-Id خطای عمومی را بدون افشای SDK به لاگ API مرتبط می‌کند.

[پایداری درخواست](admin-request-reliability.fa.md)، [مالکیت صفحه‌های مدیریتی](business-screens.fa.md) و آزمون‌های منتشرشدهٔ client/token/auth/logout و قابلیت‌ها را ببینید. مسیر کامل مرورگر برای قابلیت اطمینان درخواست متعلق به مرحلهٔ اجرایی آینده است.

## عیب‌یابی درخواست

پیش از تغییر تنظیم، URL ناموفق، وضعیت HTTP و X-Request-Id را بررسی کنید. VITE_API_BASE_URL و مبدأ مجاز API باید با scheme، نام میزبان و پورت مرورگر هماهنگ باشد؛ localhost و 127.0.0.1 مبدأ متفاوت‌اند. پس از تغییر تنظیم عمومی ساخت، Vite را دوباره اجرا کنید. ۴۰۱ تکرارشده پس از refresh و retry محدود به بررسی نشست و حساب، و ۴۰۳ به بررسی مجوز API نیاز دارد. برای حفاظت مدیر با وضعیت ۴۰۹، وضعیت فعلی حساب را دوباره بخوانید و تغییر موردنظر را با مالک API هماهنگ کنید.
