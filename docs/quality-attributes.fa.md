# ویژگی‌های کیفیت و شواهد

[English](quality-attributes.md) · [فارسی](quality-attributes.fa.md)

هر ادعا را با [سیاست انتشار](../.github/bootstrap-policy.json)، [فهرست سورس](bootstrap.fa.md)، [گیت مرجع](../.agents/validation.json) و نتیجهٔ اجرای واقعی revision بررسی‌شده بسنجید. اعلام قابلیت و وجود فرمان، اجرای موفق را ثابت نمی‌کند.

| ویژگی         | شاهد و محدودیت                                                                                                                                                                                                                              |
| ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| درستی         | تست واحد و React، ماژول منتشرشده را با HTTP ساختگی و fixture نسل نشست می‌سنجد. Storybook تعامل جداگانه را بررسی می‌کند. بررسی مجاز مرورگر برنامه به نتیجهٔ مستقل revision فعلی نیاز دارد؛ مسیر ساختگی، ارائه‌دهندهٔ واقعی را تأیید نمی‌کند. |
| مالکیت        | نگهبان AST مرز منبع از قرارداد محلی، کاتالوگ تخت و راه‌انداز اجرا حفاظت می‌کند. API مستقل مالک اجرای احراز هویت، پایگاه داده، ذخیره‌سازی و فرادادهٔ زبان فعال است.                                                                          |
| دسترس‌پذیری   | ممیزی واقعی Storybook نقض را خطا می‌داند. بررسی صفحه‌کلید برنامه، بازبینی صفحه‌خوان و تأیید انسانی مرجع تصویری، شواهد جداگانه با محدودهٔ مستقل هستند.                                                                                       |
| نگهداری‌پذیری | اعتبارسنجی مرجع، CI معنایی، بررسی مسیریابی و ارزیابی و تست راهنما از هماهنگی حفاظت می‌کنند. پیوند ایستا فهم را نشان نمی‌دهد.                                                                                                                |
| پوشش و امنیت  | LCOV واقعی واحد و راهبری، آستانهٔ پوشش بدون کاهش، audit وابستگی و Sonar بومی خطرهای متفاوتی را می‌سنجند. هیچ‌کدام نبود آسیب‌پذیری را ثابت نمی‌کند؛ استثنای منبع یا بررسی ضعیف‌تر نباید شکست را پنهان کند.                                   |

شکست، انتظار، کنارگذاری، وضعیت توصیه‌ای و دستی را صریح گزارش کنید. بودجهٔ ساخت، E2E برنامه، مقایسهٔ بصری و بررسی کارایی به مجازبودن در سیاست فعلی و اجرای واقعی نیاز دارند. بازیابی عملیاتی و هر گردش‌کار اضافهٔ CodeQL یا mutation شاهد مستقل دارای مجوز لازم دارند؛ وجود ابزار سورس به‌تنهایی استقرار یا بازیابی را ثابت نمی‌کند. [اعتبارسنجی](validation.fa.md)، [محدودهٔ Storybook](storybook-verification.fa.md) و [ارزیابی درک](comprehension-evaluation.fa.md) را به کار ببرید؛ شاهد تاریخی یا مخزن دیگر را جای نتیجهٔ head فعلی نگذارید.
