# مرحلهٔ انتشار بررسی برنامه

[English](bootstrap.md) · [فارسی](bootstrap.fa.md)

مرحلهٔ `assistant-guidance` محیط مؤلفه را با قواعد و skillهای مرجع انگلیسی دستیار، hook محلی، مسیریابی وظیفه و روش ارزیابی فقط خواندنی گسترش می‌دهد. توضیح انسانی همراه کامل انگلیسی و فارسی دارد. [فهرست مرجع](../.agents/validation.json)، بررسی هماهنگی راهنما را بدون حذف بررسی به‌ارث‌رسیده اضافه می‌کند.

[سیاست انتشار](../.github/bootstrap-policy.json) مرحلهٔ **application-verification** را با مقدار
`applicationReady: true` اعلام می‌کند. این مرحله ده کاتالوگ کامل و تخت، فهرست کدها،
دادهٔ خالص تقویم فارسی و تست‌های درستی آن‌ها را در کنار وضعیت توکن، قراردادهای انتقال
و پروفایل، تبدیل کلیدهای HTTP و ابزار کنتراست ارائه می‌کند. راه‌انداز واقعی i18next/react-i18next با فارسی ثابت آغاز می‌شود و
Day.js/Jalaliday نه زبان کتابخانه را همراه با دادهٔ محلی فارسی ثبت می‌کند. نرمال‌سازی کد و پیام خطای ترجمه‌شده نیز
منتشر شده‌اند و با وابستگی‌های واقعی در Node آزموده می‌شوند. [کلاینت HTTP و قابلیت‌ها](http-client.fa.md)، اعتبارسنجی کامل تنظیمات سرور، واژگان خالص ظاهر و [چرخهٔ درخواست](request-lifecycle.fa.md) نیز منتشر شده‌اند. تست‌ها Axios واقعی با MSW بسته در برابر شبکهٔ اعلام‌نشده و هوک واقعی React در jsdom جداگانه را بررسی می‌کنند. مرحلهٔ فعلی نقطهٔ ورود مستقل، ترکیب App و Routes و بررسی واقعی برنامه را نیز می‌پذیرد؛ اجرای واقعی همچنان شاهد جداگانه است.
[README](../README.fa.md) مالکیت سورس، [بومی‌سازی](localization.fa.md) قواعد کاتالوگ
و [راهنمای مشارکت](../CONTRIBUTING.fa.md) سیاست اعتبارسنجی و بررسی را توضیح می‌دهند.

[زیرساخت رابط کاربری](ui-foundation.fa.md) هفت مؤلفهٔ Ant Design، راه‌انداز پوسته و ترجیحات و گزارش اختیاری، رفتار بازگشت مسیر و شش دارایی محلی بررسی‌شده را اضافه می‌کند. [Core و احراز هویت](core-auth.fa.md) ارائه‌دهنده‌های Core و Ant Design، فرادادهٔ تایپ‌شدهٔ دسترسی و راهبری، فرم‌های احراز هویت و ماژول‌های چیدمان را اضافه می‌کند. [صفحه‌های مدیریتی](business-screens.fa.md) حساب، کاربران و نقش‌ها، تنظیمات، تقویم و قاب داشبورد را با حفاظت تغییر داده و مجوز اضافه می‌کند. [اعتبارسنجی Storybook](storybook-verification.fa.md) تمام storyهای ثبت‌شده، mock کامل مالکان API ساختگی، ساخت ایستای محیط مؤلفه و تست واقعی تعامل و دسترس‌پذیری در Chromium را اضافه می‌کند. مرجع تعداد دقیق فایل‌های نگهداری‌شده، فهرست سیاست است؛ اختلاف مستقل هر PR همچنان حداکثر ۱۰۰ فایل است. راه‌اندازی برنامه در src/main.tsx، src/app/App.tsx و src/app/Routes.tsx است؛ ارائه‌دهندهٔ مستقل API خارج این مخزن می‌ماند.

## نسخهٔ دقیق فایل‌ها

کنترل فهرست فایل‌ها، وجود دقیق فایل‌های نگهداری‌شدهٔ اعلام‌شده را الزامی می‌کند و
سورس اضافی، مسیر خصوصی و پیوند نمادین را نمی‌پذیرد. فقط پوشه‌های تولیدشدهٔ صریحاً
اعلام‌شده، از جمله `node_modules`، `coverage` و `dist` پذیرفته‌شدهٔ برنامه در ریشه، همراه با اطلاعات Git، خارج از
فهرست نگهداری‌شده هستند. خروجی ایستای Storybook در `coverage/storybook-static` قرار می‌گیرد. فایل‌های
untracked برنامه در پوشهٔ اطراف نباید انتشار ناقص را کامل جلوه دهند.

فهرست کل می‌تواند از ۱۰۰ فایل بیشتر شود. **سقف ۱۰۰ فایل هر PR** جداگانه بر اختلاف
GitHub اعمال می‌شود و افزودن، حذف، تغییر نام و فایل باینری را حساب می‌کند.

## بررسی کامل این مرحله

از [`.nvmrc`](../.nvmrc)، محدودهٔ Node در
[`package.json`](../package.json) و npm همراه همان نسخهٔ Node.js استفاده کنید:

```sh
npm ci
npm run browser:install
npm run validate -- full
```

[فهرست مرجع](../.agents/validation.json) تمام بررسی‌های الزامی مرحلهٔ فعلی را تعیین می‌کند:
فهرست دقیق فایل‌ها، سیاست معنایی CI، audit، مرزهای سورس، تایپ‌ها، lint، قالب‌بندی، هر دو
اجرای تست اندازه‌گیری‌شده، `build-storybook`، `test:storybook` و هماهنگی راهنما؛ تحلیل کد بلااستفاده، ساخت production، بودجهٔ bundle، قرارداد مصرف‌کنندهٔ Pact، E2E برنامه، مقایسهٔ تصویر و Lighthouse نیز اضافه می‌شوند و نوزده بررسی الزامی را می‌سازند. تست واحد در Node یا
jsdom جداگانه با کشف غیرفعال فایل محیطی اجرا می‌شود. Storybook تنظیم مستقل Vite،
mock کامل قابلیت‌ها و کلاینت و Chromium واقعی و بدون پنجره دارد. تمام storyهای ثبت‌شده
assertionهای play و ممیزی دسترس‌پذیری را با تبدیل نقض‌ها به خطا اجرا می‌کنند. بررسی برنامه preview و مرورگر متعلق به آزمون را راه می‌اندازد؛ API بیرونیِ در حال اجرا یا محیط و وضعیت واقعی لازم نیست.

انتشار اولیه به‌صورت مرحله‌ای و با سقف ۱۰۰ فایل هر PR پیش می‌رود. هر PR تمام
بررسی‌های محدودهٔ منتشرشده را با همان فرمان محلی `npm run validate -- full` اجرا
می‌کند و مسیرهای تغییرکرده مبنای انتخاب تست نیستند. CI فهرست جداگانه‌ای از بررسی‌ها
ندارد. اجراکننده پیش از اجرای فرمان‌ها، برنامهٔ منتخب را اعتبارسنجی می‌کند: تعریف
تکراری بررسی یا ورودی پروفایل، شناسهٔ ناشناخته، نبود بررسی الزامی و ورود بررسی دستی
یا مشورتی به `full` باعث شکست می‌شود. پروفایل‌های محدود کمک‌ابزار توسعه هستند؛ با
انتشار سورس و پیش از ادغام پنل قابل اجرا، بررسی‌های برنامه به همین گیت کامل
اضافه می‌شوند.

بررسی سیاست CI، YAML را با کلیدهای یکتا می‌خواند و نصب بدون شرط وابستگی، سپس مرورگر و سپس یک بررسی کامل مرجع بدون شرط را لازم می‌داند. فیلتر مسیر و شاخهٔ PR، حذف رویداد لازم، اجرای مشورتی یا شرطی بررسی، اجرا بیرون ریشه و تغییر shell رد می‌شوند. شرط محدودیت فایل یا بارگذاری artifact، بررسی را اختیاری نمی‌کند. تمام بررسی‌های الزامی در `check` می‌مانند و مالکیت واقعی کارهای build/e2e/visual نیز صریح است. workflow برنامه و scanner پیش‌نیاز Windows همسان دارند؛ نتیجهٔ واقعی head فعلی را جدا بررسی کنید.

تست‌های واحد `coverage/unit/lcov.info` و تست‌های قواعد مخزن در Node گزارش
`coverage/governance/lcov.info` را تولید می‌کنند. هر دو در همین checkout اندازه‌گیری و
در [Sonar](sonarqube.fa.md) وارد می‌شوند. گزارش ساختگی نسازید و این پوشش منتخب را
پوشش پنل کامل معرفی نکنید. تست دادهٔ کاتالوگ و درستی تقویم در همان مجموعهٔ تست واحد
اجرا می‌شود و پوشش واقعی همین ماژول‌های منتشرشده را تولید می‌کند.

## بررسی میزبانی‌شده

[CI](../.github/workflows/ci.yml) نسخهٔ منتشرشده را اعتبارسنجی می‌کند.
[سیاست PR](../.github/workflows/pr-policy.yml) با دسترسی فقط‌خواندنی، کد مورد اعتماد
شاخهٔ پیش‌فرض را با ارجاع ثابت `github.workflow_sha` اجرا می‌کند. در رویداد
`pull_request_target` نباید کد شاخهٔ PR اجرا شود.

Workflow سیاست PR روی شاخهٔ پیش‌فرض منتشر شده است و سقف ۱۰۰ فایل را با کد مورد اعتماد
همان شاخه بررسی می‌کند. CI معمول PR با دسترسی عادی نیز کنترل فقط‌خواندنی تعداد فایل
را در ابتدا اجرا می‌کند. نتیجهٔ واقعی میزبانی‌شده را برای نسخهٔ پیشنهادی تأیید کنید؛
وجود workflow شاهد اجرا نیست.

بررسی CodeRabbit فقط دستی است. پیش از درخواست،
[پیش‌بررسی آخرین نسخه](../CONTRIBUTING.fa.md#پیش-از-درخواست-coderabbit) را کامل کنید:
تمام بررسی‌های الزامیِ مرحلهٔ منتشرشده، غیر از خود CodeRabbit، از جمله scanner و
دروازهٔ کیفیت واقعی Sonar باید موفق باشند و کل گزارش مرتبط Sonar
در همهٔ شدت‌ها و کد قدیمی و جدید، صفر مسئلهٔ باز یا حل‌نشده داشته باشد. نبود شاهد یا
مثبت کاذبِ مستندشدهٔ باز مانع درخواست است؛ کامیت جدید پیش‌بررسی را نامعتبر می‌کند.
بررسی و تأیید خود CodeRabbit فقط برای جلوگیری از چرخه کنار گذاشته می‌شود. مجوز،
سهمیهٔ موجود و نبود درخواست هم‌زمان تکراری الزامی است.
[حفاظت شاخه](branch-protection.fa.md) را رعایت کنید.

## آمادگی پنل قابل اجرا

نتیجه‌های بومی CI و سرویس‌های پیشین الزامی می‌مانند. منبع برنامه اکنون کار واقعی ساخت، E2E و تصویر را فراهم می‌کند و `check` تمام نوزده بررسی پروفایل کامل را اجرا می‌کند. کار ساختگیِ موفق یا بررسی اجرا‌نشده را شاهد معرفی نکنید.

پیش از ادغام پنل اجرایی، موفقیت واقعی build/e2e/visual در head فعلی را مشاهده و برای افزودن نتیجه‌های بومی آن‌ها به حفاظت زنده مجوز بگیرید؛ تمام تنظیمات قبلی حفظ شوند. اعلام مرحلهٔ منبع حفاظت راه‌دور را فعال نمی‌کند، ارائه‌دهندهٔ مستقل API را بررسی نمی‌کند و مجوز استقرار نیست. [حفاظت شاخه](branch-protection.fa.md) را رعایت کنید.

## پیش‌نیازهای محدود عملیات و کیفیت

مرحلهٔ قبلی assistant-guidance هفتاد پیش‌نیاز نگهداری‌شده اضافه کرد و فهرست آن با applicationReady برابر false به ۴۳۶ رسید. مرحلهٔ فعلی application-verification آن‌ها را حفظ و مجموعهٔ محدود برنامه را می‌پذیرد؛ در نتیجه ۴۷۱ مسیر نگهداری می‌شوند. تعداد فهرست با تعداد فایل‌های تغییرکردهٔ PR یکی نیست.

استثناهای دقیق نمونه فقط `.env.example`، `deploy/docker/.env.example` و `deploy/native/hosts.env.example` هستند. فقط منبع ساختگی Git که عمداً اعلام و بازبینی شده باشد پذیرفته است؛ فایل محیطی دلخواه، اطلاعات ورود و وضعیت واقعی اپراتور همچنان ممنوع‌اند. چهار PNG و فرادادهٔ آن‌ها بایت و تاریخ بازبینی تاریخی را حفظ می‌کنند، نه تأیید فعلی را.

مورد واحد خالص و تست ساختگی governance و چرخهٔ منابع همچنان یک‌بار در همان دو فرمان پوشش اجرا می‌شوند. full اکنون نوزده ورودی الزامی دارد و تعریف مشورتیِ پروفایل متمرکز راهنما حفظ شده است. فرمان استقرار یا پروفایل اپراتور از این متن نتیجه نمی‌شود. سورس یا تست ابزار، اجرای واقعی ارائه‌دهنده، Docker، staging، mutation یا استقرار را ثابت نمی‌کند. [استقرار](deployment.fa.md)، [محدودهٔ پوشش](component-coverage.fa.md) و [سابقهٔ تصویر](visual-regression.fa.md) را بخوانید.

اجراگر تصویر و Lighthouse و ثبت فرادادهٔ ساخت هنگام import همچنان بی‌اثرند. تست چرخه و منشأ با وابستگی تزریق‌شده، برنامه، Chrome یا API راه نمی‌اندازد. فرمان‌های پذیرفته‌شدهٔ برنامه جداگانه preview و مرورگر متعلق به آزمون را با دادهٔ ساختگی اجرا می‌کنند؛ منشأ همسان محیط اجرا، تأیید واقعی انسانی تصویر و ممنوعیت به‌روزرسانی در CI را حفظ کنید. عملیات ارائه‌دهنده، Docker، staging و استقرار مجوز و شاهد مستقل لازم دارند.
