# مرحلهٔ انتشار راهنمای دستیار

[English](bootstrap.md) · [فارسی](bootstrap.fa.md)

مرحلهٔ `assistant-guidance` محیط مؤلفه را با قواعد و skillهای مرجع انگلیسی دستیار، hook محلی، مسیریابی وظیفه و روش ارزیابی فقط خواندنی گسترش می‌دهد. توضیح انسانی همراه کامل انگلیسی و فارسی دارد. [فهرست مرجع](../.agents/validation.json)، بررسی هماهنگی راهنما را بدون حذف بررسی به‌ارث‌رسیده اضافه می‌کند.

[سیاست انتشار](../.github/bootstrap-policy.json) مرحلهٔ **assistant-guidance** را با مقدار
`applicationReady: false` اعلام می‌کند. این مرحله ده کاتالوگ کامل و تخت، فهرست کدها،
دادهٔ خالص تقویم فارسی و تست‌های درستی آن‌ها را در کنار وضعیت توکن، قراردادهای انتقال
و پروفایل، تبدیل کلیدهای HTTP و ابزار کنتراست ارائه می‌کند. راه‌انداز واقعی i18next/react-i18next با فارسی ثابت آغاز می‌شود و
Day.js/Jalaliday نه زبان کتابخانه را همراه با دادهٔ محلی فارسی ثبت می‌کند. نرمال‌سازی کد و پیام خطای ترجمه‌شده نیز
منتشر شده‌اند و با وابستگی‌های واقعی در Node آزموده می‌شوند. [کلاینت HTTP و قابلیت‌ها](http-client.fa.md)، اعتبارسنجی کامل تنظیمات سرور، واژگان خالص ظاهر و [چرخهٔ درخواست](request-lifecycle.fa.md) نیز منتشر شده‌اند. تست‌ها Axios واقعی با MSW بسته در برابر شبکهٔ اعلام‌نشده و هوک واقعی React در jsdom جداگانه را بررسی می‌کنند. این محدوده پنل قابل اجرا نیست.
[README](../README.fa.md) مالکیت سورس، [بومی‌سازی](localization.fa.md) قواعد کاتالوگ
و [راهنمای مشارکت](../CONTRIBUTING.fa.md) سیاست اعتبارسنجی و بررسی را توضیح می‌دهند.

[زیرساخت رابط کاربری](ui-foundation.fa.md) هفت مؤلفهٔ Ant Design، راه‌انداز پوسته و ترجیحات و گزارش اختیاری، رفتار بازگشت مسیر و شش دارایی محلی بررسی‌شده را اضافه می‌کند. [Core و احراز هویت](core-auth.fa.md) ارائه‌دهنده‌های Core و Ant Design، فرادادهٔ تایپ‌شدهٔ دسترسی و راهبری، فرم‌های احراز هویت و ماژول‌های چیدمان را اضافه می‌کند. [صفحه‌های مدیریتی](business-screens.fa.md) حساب، کاربران و نقش‌ها، تنظیمات، تقویم و قاب داشبورد را با حفاظت تغییر داده و مجوز اضافه می‌کند. [اعتبارسنجی Storybook](storybook-verification.fa.md) تمام storyهای ثبت‌شده، mock کامل مالکان API ساختگی، ساخت ایستای محیط مؤلفه و تست واقعی تعامل و دسترس‌پذیری در Chromium را اضافه می‌کند. مرجع تعداد دقیق فایل‌های نگهداری‌شده، فهرست سیاست است؛ اختلاف مستقل هر PR همچنان حداکثر ۱۰۰ فایل است. نقطهٔ ورود برنامه و ترکیب App و Routes منتشر نمی‌شوند.

## نسخهٔ دقیق فایل‌ها

کنترل فهرست فایل‌ها، وجود دقیق فایل‌های نگهداری‌شدهٔ اعلام‌شده را الزامی می‌کند و
سورس اضافی، مسیر خصوصی و پیوند نمادین را نمی‌پذیرد. فقط پوشه‌های تولیدشدهٔ صریحاً
اعلام‌شده، از جمله `node_modules` و `coverage` در ریشه، همراه با اطلاعات Git، خارج از
فهرست نگهداری‌شده هستند. خروجی ایستای Storybook در `coverage/storybook-static` قرار می‌گیرد. فایل‌های
untracked برنامه در پوشهٔ اطراف نباید انتشار ناقص را کامل جلوه دهند.

فهرست کل می‌تواند از ۱۰۰ فایل بیشتر شود. **سقف ۱۰۰ فایل هر PR** جداگانه بر اختلاف
GitHub اعمال می‌شود و افزودن، حذف، تغییر نام و فایل باینری را حساب می‌کند.

## بررسی کامل این مرحله

از [`.nvmrc`](../.nvmrc)، محدودهٔ Node در
[`package.json`](../package.json) و npm همراه همان نسخهٔ Node.js استفاده کنید:

```sh
npm ci
npm run browser:install
npm run validate -- full
```

[فهرست مرجع](../.agents/validation.json) تمام بررسی‌های الزامی مرحلهٔ فعلی را تعیین می‌کند:
فهرست دقیق فایل‌ها، سیاست معنایی CI، audit، مرزهای سورس، تایپ‌ها، lint، قالب‌بندی، هر دو
اجرای تست اندازه‌گیری‌شده، `build-storybook`، `test:storybook` و هماهنگی راهنما. تست واحد در Node یا
jsdom جداگانه با کشف غیرفعال فایل محیطی اجرا می‌شود. Storybook تنظیم مستقل Vite،
mock کامل قابلیت‌ها و کلاینت و Chromium واقعی و بدون پنجره دارد. تمام storyهای ثبت‌شده
assertionهای play و ممیزی دسترس‌پذیری را با تبدیل نقض‌ها به خطا اجرا می‌کنند. پنل در
حال اجرا، فرآیند API یا محیط و وضعیت واقعی لازم نیست.

انتشار اولیه به‌صورت مرحله‌ای و با سقف ۱۰۰ فایل هر PR پیش می‌رود. هر PR تمام
بررسی‌های محدودهٔ منتشرشده را با همان فرمان محلی `npm run validate -- full` اجرا
می‌کند و مسیرهای تغییرکرده مبنای انتخاب تست نیستند. CI فهرست جداگانه‌ای از بررسی‌ها
ندارد. اجراکننده پیش از اجرای فرمان‌ها، برنامهٔ منتخب را اعتبارسنجی می‌کند: تعریف
تکراری بررسی یا ورودی پروفایل، شناسهٔ ناشناخته، نبود بررسی الزامی و ورود بررسی دستی
یا مشورتی به `full` باعث شکست می‌شود. پروفایل‌های محدود کمک‌ابزار توسعه هستند؛ با
انتشار سورس و پیش از ادغام پنل قابل اجرا، بررسی‌های برنامه به همین گیت کامل
اضافه می‌شوند.

بررسی سیاست CI، فایل YAML را با کلیدهای یکتا تجزیه می‌کند و یک اجرای بدون شرط
`npm ci` و سپس `npm run browser:install` را پیش از یک اجرای بدون شرط فرمان کامل مرجع الزامی می‌داند. فیلتر مسیر یا
شاخهٔ PR، حذف رویدادهای لازم، اجرای شرطی یا مشورتی بررسی، پوشهٔ کاری بیرون از ریشه
و تغییر shell رد می‌شوند. شرطِ مراحل دیگر مانند کنترل تعداد فایل PR یا بارگذاری
گزارش، اعتبارسنجی را اختیاری نمی‌کند. سیاست فعلی تمام بررسی‌های الزامی، از جمله ساخت و
مرورگر Storybook را در کار `check` نگه می‌دارد؛ پیش از افزودن کار جداگانهٔ برنامه یا
تصویر در ویندوز، اجرای متناسب با هر کار را اضافه و این سیاست را صریحاً به‌روز کنید.

تست‌های واحد `coverage/unit/lcov.info` و تست‌های قواعد مخزن در Node گزارش
`coverage/governance/lcov.info` را تولید می‌کنند. هر دو در همین checkout اندازه‌گیری و
در [Sonar](sonarqube.fa.md) وارد می‌شوند. گزارش ساختگی نسازید و این پوشش منتخب را
پوشش پنل کامل معرفی نکنید. تست دادهٔ کاتالوگ و درستی تقویم در همان مجموعهٔ تست واحد
اجرا می‌شود و پوشش واقعی همین ماژول‌های منتشرشده را تولید می‌کند.

## بررسی میزبانی‌شده

[CI](../.github/workflows/ci.yml) نسخهٔ منتشرشده را اعتبارسنجی می‌کند.
[سیاست PR](../.github/workflows/pr-policy.yml) با دسترسی فقط‌خواندنی، کد مورد اعتماد
شاخهٔ پیش‌فرض را با ارجاع ثابت `github.workflow_sha` اجرا می‌کند. در رویداد
`pull_request_target` نباید کد شاخهٔ PR اجرا شود.

Workflow سیاست PR روی شاخهٔ پیش‌فرض منتشر شده است و سقف ۱۰۰ فایل را با کد مورد اعتماد
همان شاخه بررسی می‌کند. CI معمول PR با دسترسی عادی نیز کنترل فقط‌خواندنی تعداد فایل
را در ابتدا اجرا می‌کند. نتیجهٔ واقعی میزبانی‌شده را برای نسخهٔ پیشنهادی تأیید کنید؛
وجود workflow شاهد اجرا نیست.

بررسی CodeRabbit فقط دستی است. پیش از درخواست،
[پیش‌بررسی آخرین نسخه](../CONTRIBUTING.fa.md#پیش-از-درخواست-coderabbit) را کامل کنید:
تمام بررسی‌های الزامیِ مرحلهٔ منتشرشده، غیر از خود CodeRabbit، از جمله scanner و
دروازهٔ کیفیت واقعی Sonar باید موفق باشند و کل گزارش مرتبط Sonar
در همهٔ شدت‌ها و کد قدیمی و جدید، صفر مسئلهٔ باز یا حل‌نشده داشته باشد. نبود شاهد یا
مثبت کاذبِ مستندشدهٔ باز مانع درخواست است؛ کامیت جدید پیش‌بررسی را نامعتبر می‌کند.
بررسی و تأیید خود CodeRabbit فقط برای جلوگیری از چرخه کنار گذاشته می‌شود. مجوز،
سهمیهٔ موجود و نبود درخواست هم‌زمان تکراری الزامی است.
[حفاظت شاخه](branch-protection.fa.md) را رعایت کنید.

## آمادگی پنل قابل اجرا

حفاظت مرحلهٔ assistant-guidance، بررسی‌های منتشرشدهٔ CI و سرویس‌ها را طبق
[حفاظت شاخه](branch-protection.fa.md) الزامی می‌کند. ساخت ایستای محیط مؤلفه و بررسی
مرورگر و دسترس‌پذیری جداگانه در `check` اجرا می‌شوند؛ این‌ها ساخت پنل محصول، مسیر
E2E کامل برنامه یا کار مقایسهٔ تصویری نیستند. کار ساختگی با نتیجهٔ موفق نسازید و
بررسی اجرا‌نشده را شاهد معرفی نکنید.

نقطهٔ ورود واقعی React/Vite و ترکیب App و Routes، ساخت نهایی و شواهد
مرورگر، دسترس‌پذیری، کارایی و تصویر را در کارهای منسجم بعدی اضافه کنید. پیش از ادغام
هر پنل قابل اجرا، فهرست فایل‌ها و بررسی کامل مرجع را گسترش دهید، موفقیت کارهای واقعی
ساخت، تست سرتاسری و تصویری را مشاهده کنید و آن‌ها را به بررسی‌های الزامی اضافه کنید.
موفقیت بررسی مرحلهٔ assistant-guidance آن
نتایج را از پیش ثابت نمی‌کند.

## پیش‌نیازهای محدود عملیات و کیفیت

همان شناسهٔ `assistant-guidance` اکنون عمداً ۷۰ مسیر نگهداری‌شدهٔ دیگر را شامل می‌شود و فهرست اعلام‌شده را به ۴۳۶ مسیر می‌رساند. نمونه‌های عمومیِ ساختگی و بازبینی‌شده، منبع ابزار نسخه و استقرار، سیاست خالص bundle و Lighthouse و مقصد، راهنمای عملیاتی کامل انگلیسی و فارسی و سابقهٔ تصویری تاریخ‌دار اضافه می‌شوند. `applicationReady: false`، همهٔ بررسی‌های قبلی و رد فایل ورودی و ساختِ خارج از برنامهٔ انتشار حفظ می‌شوند.

استثناهای دقیق نمونه فقط `.env.example`، `deploy/docker/.env.example` و `deploy/native/hosts.env.example` هستند. فقط منبع ساختگی Git که عمداً اعلام و بازبینی شده باشد پذیرفته است؛ فایل محیطی دلخواه، اطلاعات ورود و وضعیت واقعی اپراتور همچنان ممنوع‌اند. چهار PNG و فرادادهٔ آن‌ها بایت و تاریخ بازبینی تاریخی را حفظ می‌کنند، نه تأیید فعلی را.

مورد واحد خالص و مورد ساختگیِ governance و چرخهٔ منابع در همان دو فرمان پوشش موجود اجرا می‌شوند. full همچنان دوازده بررسی الزامی و سیزده تعریف ثبت‌شده دارد؛ فرمان عملیاتی یا پروفایل متمرکز تازه اضافه نشده است. وجود کد ابزار، اجرای ساخت production، Docker یا Chrome واقعی، provider و E2E، تصویر، Lighthouse، mutation یا استقرار نیست. [استقرار](deployment.fa.md)، [دامنهٔ پوشش](component-coverage.fa.md) و [تاریخچهٔ تصویر](visual-regression.fa.md) را ببینید.

آماده‌سازی اجراگرِ بررسی، هماهنگ‌سازی تصویر و Lighthouse و ثبت فرادادهٔ ساخت را بدون اثر هنگام import اضافه می‌کند. آزمون ساختگی، مالکیت منابع و پاک‌سازی هنگام شکست و منشأ را بدون راه‌اندازی برنامه، Chrome یا API می‌سنجد. فرمان npm عملیاتی ثبت نمی‌شود؛ گیت فعلیِ دوازده‌بررسی و الزام بازبینی انسانی تصویر تغییر نمی‌کنند. پذیرش CI برنامهٔ آینده جدا از workflow فعلی Linux آزموده می‌شود.
