# مالکیت کاتالوگ‌های محلی

[English](localization.md) · [فارسی](localization.fa.md)

[مرحلهٔ کاتالوگ‌های فعلی](bootstrap.fa.md) دادهٔ خالص ترجمه و تقویم محلی را منتشر
می‌کند. این مرحله i18next، React، کتابخانه‌های تاریخ یا مرورگر را راه‌اندازی نمی‌کند.
مقدار `applicationReady:false` همچنان آگاهانه حفظ می‌شود.

## یک کاتالوگ برای هر زبان

[`src/shared/i18n/locales.ts`](../src/shared/i18n/locales.ts) مالک ده کد کاتالوگ
پشتیبانی‌شده است: `ar`، `de`، `en`، `es`، `fa`، `fr`، `it`، `pt`، `ru` و `tr`.
هر کد دقیقاً یک فایل `locales/<code>.ts` و یک شیء کامل با ۱۱۰ پیام رشته‌ای در ریشه
دارد. [`catalogs.ts`](../src/shared/i18n/catalogs.ts) همان اشیا را مستقیم ثبت می‌کند؛
شیء کپی‌شده یا سازگاری موقت نسازید.

پیش از افزودن برچسب دیگر، از کلید معنایی موجود در ریشه استفاده کنید. شیء تودرتوی
`common`، پیشوند `common.`، فایل‌های جداگانهٔ admin/common، پوشهٔ جدا برای هر زبان یا
نام‌های جایگزین قدیمی اضافه نکنید. ترجمه‌ها باید غیرخالی و واقعی باشند؛ گسترش شیء
انگلیسی، کپی متن انگلیسی به‌عنوان جای‌نگهدار و fallback زمان اجرا، ترجمه محسوب
نمی‌شوند. نام متغیرهای جایگذاری i18next مانند `{{variable}}` را در همهٔ زبان‌ها حفظ
کنید. کاتالوگ انگلیسی شکل کلیدها را تعیین می‌کند و بقیهٔ کاتالوگ‌ها با تایپ
`TranslationCatalog` که در زمان اجرا حذف می‌شود، با آن همخوان می‌مانند.

فایل‌های برگ کاتالوگ در `locales/<code>.ts`، فرادادهٔ کدها در `locales.ts` و دادهٔ
تقویم در `dayjs/fa.ts` فقط می‌توانند تایپ‌های محلی مانند `TranslationCatalog` را
وارد کنند که کاملاً در زمان اجرا حذف می‌شوند. بارگذاری دادهٔ جایگزین از طریق
واردسازی یا بازصادرات زمان اجرا، واردسازی پویا یا `require` مجاز نیست. فقط فهرست
`catalogs.ts` می‌تواند اشیای مرجع کاتالوگ محلی را در زمان اجرا بارگذاری کند. موتور
ترجمه، کتابخانهٔ رابط کاربری، بستهٔ تاریخ و سورس پوشهٔ پروژهٔ دیگر در این ماژول‌های
داده جایی ندارند.
API و وب‌سایت مستقل، کاتالوگ‌ها و قراردادهای خود را دارند؛ سورس آن‌ها وابستگی زمان
اجرای این برنامه نیست.

## مرجع زبان و دادهٔ تقویم

فهرست کدها فقط کاتالوگ‌های محلی موجود را مشخص می‌کند. زبان فعال، جهت، تقویم، نام
عمومی و نام بومی متعلق به API است. آداپترهای HTTP و زمان اجرای آینده باید تمام این
فراداده را اعتبارسنجی و حفظ کنند و نباید جهت یا تقویم را از کد زبان حدس بزنند. انتخابگر
زبان برای بازدیدکننده یا ترجیح زبانِ ذخیره‌شده در مرورگر نداریم. فقط مدیر کل سیستم
می‌تواند زبان فعال را از طریق تنظیمات API تغییر دهد.

زمان اجرای آینده تا دریافت تنظیمات معتبر API با راه‌اندازی ثابت فارسی آغاز می‌شود و
باید رفتار روشن خطا و تلاش مجدد را حفظ کند. این fallback هیچ‌وقت نبود ترجمه را توجیه
نمی‌کند. ترجیح پوسته و حالت فشرده موضوعاتی جدا هستند. بارگذاری زبان، تغییر زبان در
زمان اجرا و رفتار مرورگر در این مرحلهٔ دادهٔ خالص پیاده‌سازی یا تأیید نمی‌شوند.

[`dayjs/fa.ts`](../src/shared/i18n/dayjs/fa.ts) دادهٔ خالص فارسی برای کتابخانهٔ تقویم
است و از پیام‌های رابط کاربری جدا می‌ماند. ماه‌های میلادی `months` را از ماه‌های
جلالی `jmonths` جدا و دادهٔ روزهای هفته، قالب‌ها و زمان نسبی را کامل حفظ کنید. ساختار
این شیء دادهٔ کتابخانه است؛ کاتالوگ پیام تودرتو یا تنظیم تقویم فعال نیست. آداپتر
تاریخ آینده باید زبان‌های واقعی کتابخانه را ثبت و تقویم انتخاب‌شده در API را استفاده
کند؛ این داده به‌تنهایی رفتار نمایش تاریخ را ثابت نمی‌کند.

## بررسی درستی و شواهد

[`catalogs.test.ts`](../src/shared/i18n/catalogs.test.ts) کلیدهای کامل و غیرخالی ریشه،
همخوانی متغیرها، یک فایل هم‌نام کد برای هر زبان ثبت‌شده، هویت شیء مرجع، واردسازی
خالص، نبود کاتالوگ‌های جداشده و فراخوان‌های سورس منتشرشده را بررسی می‌کند. بررسی
فراخوان‌ها فقط سورسی را پوشش می‌دهد که واقعاً اینجا منتشر شده است و پوشش رابط کاربری،
Storybook یا نمونه‌های مرورگرِ غایب را ادعا نمی‌کند. کیفیت و معنای ترجمه همچنان به
بازبینی انسانی نیاز دارد.

[بررسی کامل مرجع](../.agents/validation.json) را اجرا کنید:

```sh
npm ci
npm run validate -- full
```

هر نُه بررسی الزامی مرحله در هر PR، مستقل از مسیرهای تغییرکرده اجرا می‌شوند. تست‌های
کاتالوگ به اجرای موجود Vitest در محیط Node اضافه می‌شوند؛ کشف فایل محیطی غیرفعال است
و LCOV واقعی از همان checkout اندازه‌گیری می‌شود. [پیش‌بررسی Sonar و بازبینی](sonarqube.fa.md)
را حفظ کنید؛ موفقیت تست دادهٔ خالص، آماده بودن پنل قابل اجرا را ثابت نمی‌کند.

هنگام ورود آداپترهای زمان اجرا، تست‌های واقعی راه‌اندازی i18next، اعتبارسنجی زبان
API، زبان و تقویم کتابخانه، مؤلفه و مرورگر را پیش از انتشار قابل اجرا به گیت مرجع
اضافه کنید. موفقیت بررسی سورس، کارهای ساختگی یا تست فایل‌های منتشرنشده شاهد ارتباط
واقعی بخش‌ها نیستند.
