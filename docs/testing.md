# Admin testing and verification

[English](testing.md) · [فارسی](testing.fa.md)

The application-verification phase admits the composed standalone application and retains module and component-workshop assertions. Start with the smallest affected check, then validate the exact proposed snapshot through the blocking `full` profile. Use [validation policy](validation.md) for local/PR, complete compatibility and hosted visual responsibilities; local publication does not require the approved CI screenshot OS.

Unit tests use Vitest, React Testing Library and synthetic MSW responses for HTTP, lifecycle, provider, form, widget, catalog and translation/date modules. Preserve every production module in measured coverage and all existing thresholds. The dialog-focus helper and Lighthouse runner are explicitly included in the measured unit LCOV. These fixtures never use an operator API, real session, database or environment file.

Node governance tests protect the publication inventory, source boundaries, canonical runner and semantic CI/scanner policy. Guidance consistency and portable Node safety-hook regressions run in that suite. The canonical command runs files serially (`--test-concurrency=1`) so CPU-bounded child tests do not compete with other governance files; every corpus, assertion, LCOV reporter and existing deadline, including the five-second Markdown regression, stays unchanged. `npm run test:guidance` is a focused subset, not a replacement for full validation. Optional Bash wrapper cases probe a usable Bash before execution; an unavailable host prerequisite is reported as a skip while portable safety tests remain mandatory. The optional post-edit formatter uses Node to parse its input and the project-local ESLint CLI to fix only the selected file; its disposable regression verifies that unrelated files remain unchanged.

Storybook build and Chromium tests cover every registered story, real play interactions and accessibility with violations treated as errors. Feature owners and the shared HTTP client use full synthetic replacements; unexpected requests fail even when a component catches them. English/Persian toolbar metadata, direction and theme are fixtures, not visitor language preferences.

The full gate produces actual unit/governance LCOV from the checked snapshot. Browser results and static workshop assets are separate evidence. Do not commit generated output. Current-head hosted CI, scanner and native Sonar need independent verification; local success does not prove hosted execution or approval.

Application Playwright fixtures exercise routing, authentication and management with synthetic HTTP and fail-closed unexpected requests. Chromium runs in ordinary PR validation; the complete browser matrix runs in scheduled/manual pre-release verification instead of repeating Chromium first. The four authentication accessibility states have independent bounded tests while retaining every audit and keyboard assertion. Pact uses an owned local mock provider and does not verify the separate API. For failures, record the first command, revision and error; distinguish product, fixture and host causes.

## Preparatory helper suites

The four existing unit owners add bundle policy, pure Lighthouse policy, production-input and workflow-target validation. Three governance owners add deployment rendering, release packaging and Docker resource/orchestration fixtures. They run once within existing measured commands; no third required suite or focused operations profile is introduced. Imports and synthetic driver cases do not launch Docker, a browser, preview or external target.

Keep failure/cleanup assertions, stress corpora and bounded deadlines. The blocking `full` plan contains seventeen checks; hosted visual and complete compatibility checks have separate applicability, while Lighthouse follows the time-bounded exception in [performance policy](performance.md). Production coverage thresholds and measured unit/governance LCOV remain unchanged. Only declared synthetic public examples may be read; real environments, keys and operator state remain outside fixtures. See [test reliability](test-reliability.md).

Visual/Lighthouse runners and build metadata stamping remain import-safe. Injected lifecycle/provenance tests do not start the application, Chrome or an API. The visual CLI regression injects synthetic browser and child drivers to verify pending-capture provenance, isolated synthetic environment values and resource cleanup; this is governance evidence and does not generate or approve actual images. The admitted application commands separately execute owned synthetic previews and browsers; preserve matching runtime provenance, actual human image approval and the unchanged CI update prohibition. Provider, Docker, staging and deployment operation require separate authorization and evidence.

Build-metadata and release-packaging fixtures resolve the temporary parent before creating an owned directory. Their alias regressions preserve exact artifact ownership and cleanup assertions when Windows exposes the same directory through short and long path names; alternate spellings do not permit escaping the owned directory.

The production Vite UI and vendor groups partition shared modules by their actual entry consumers (`entriesAware: true`). Route-specific dependencies can stay lazy instead of joining authentication's initial module graph merely because they use the same library. Core startup uses direct provider/hook imports. One module-scope React.lazy factory loads the Ant Design provider, settings feedback and routes together only when validated settings are ready or a bootstrap error needs themed retry feedback. The loading indicator and Suspense fallback stay outside that provider; the loaded named component keeps provider and route identities across later refresh failures. The existing chunk/total bundle limits and Lighthouse throttling and thresholds still apply.

Route regressions hold matched public layout/page imports unresolved, verify that both start in parallel, and retain an accessible initial loading status and the same committed Ant Design provider through resolution. A denied page's importer must remain uncalled even if it would reject, and the dashboard redirect must still work. Permitted pages must import and render normally; rejected public and permitted protected modules must reach and report the existing error fallback. These cases preserve all existing route, settings-retry and error assertions and deadlines; they do not replace the full browser, visual or performance gate.

Language-setting confirmation cases wait for the active dialog’s opening motion to finish before the real mouse click. The Q4 Firefox trace showed a click during the entrance transition missing the moving button, with no settings PUT. Readiness synchronization preserves the original settings assertions, deadlines and zero retries.

The authentication panel applies its active foreground and background together, including native links. Failed CI check/E2E/visual and Sonar jobs retain generated synthetic browser, visual and Lighthouse diagnostics for three days.

The logout journey waits for the fullscreen loading blocker to leave before opening the account menu with its declared desktop hover or touch gesture. Its original authorization-header, redirect and login-form assertions, deadlines and zero retries remain unchanged.

Windows application E2E and Lighthouse Chromium launchers backport [Playwright's socket fix](https://github.com/microsoft/playwright/pull/43605) by adding `TcpPortRandomizationWin` to each launcher's complete existing disabled-feature list. The pinned Playwright 1.64.1 defaults and every other flag stay intact; other platforms and the reviewed visual launcher are unchanged. Remove this temporary backport when the pinned stable release includes the upstream fix. Browser versions, videos, checks, deadlines, retries and performance budgets remain unchanged.
