# ثبت بازبینی امنیتی

[English](reviews.md) · [فارسی](reviews.fa.md)

پیش از تغییر هویت، مجوز، cookie و توکن، بازیابی یا مرز انتشار، [فهرست احراز هویت](authentication-review.fa.md) و [مدل تهدید](threat-model.fa.md) را بخوانید. درخواست و دامنه، revision دقیق، بازبین و تاریخ، بازتولید ساختگی، خطر مشاهده‌شده، آزمون‌های واقعاً اجراشده و ابهام باقی‌مانده را ثبت کنید.

کنترل پیاده‌سازی‌شده، ابزار پیکربندی‌شده، سابقهٔ تاریخی و شاهد تازهٔ اجرا را جدا کنید. بررسی مرجع، بازبینی CodeRabbit و گزارش بومی Sonar دامنه‌های متفاوتی دارند. فایل workflow، گیت سبز یا PR تأییدشده تضمین نبود آسیب‌پذیری نیست. پیش از درخواست دستی بازبینی، [پیش‌بررسی کامل آخرین head](../../CONTRIBUTING.md#before-requesting-coderabbit) را حفظ کنید.

استقرار، staging و DAST، بازبینی TLS تولیدی و آزمون provider واقعی، روش‌های آیندهٔ دارای مجوز هستند. از workflow ناموجود یا آزمون ابزار خالص محلی، اجرای CodeQL، mutation، DAST یا provider نتیجه نگیرید. artifact اسکن و جزئیات قابل سوءاستفاده را خصوصی نگه دارید و از [سیاست گزارش امنیتی](../../SECURITY.fa.md) پیروی کنید.

fixture ساختگی نباید محیط اپراتور، اطلاعات ورود، پایگاه داده یا upload را بخواند. رفتار API نزد مالک مستقل آن بماند و هنگام تغییر مرز wire، تصمیم سازگاری و rollout ثبت شود.
