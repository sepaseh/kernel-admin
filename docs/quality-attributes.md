# Quality attributes and evidence

[English](quality-attributes.md) · [فارسی](quality-attributes.fa.md)

Evaluate each claim against the checked revision's [publication policy](../.github/bootstrap-policy.json), [source inventory](bootstrap.md), [canonical gate](../.agents/validation.json) and actual executed results. Capability declarations and available commands do not establish a successful run.

| Attribute             | Evidence and limits                                                                                                                                                                                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Correctness           | Unit/React tests cover published modules using synthetic HTTP and session-generation fixtures. Storybook checks isolated interactions. Admitted application browser checks need their own current-revision results; synthetic journeys do not verify real providers. |
| Ownership             | The AST boundary guard protects local contracts, flat catalogs and runtime adapters. The separate API owns authentication execution, database, storage and active language metadata.                                                                                 |
| Accessibility         | Real Storybook audits treat violations as errors. Application keyboard checks, screen-reader review and human approval of visual baselines are separate evidence with their own scope.                                                                               |
| Maintainability       | Canonical validation, semantic CI, navigation/evaluation checks and guidance regressions protect consistency. Static links do not demonstrate comprehension.                                                                                                         |
| Coverage and security | Actual unit/governance LCOV, unchanged coverage thresholds, dependency audit and native Sonar measure different risks. None proves absence of vulnerabilities; source exclusions or weaker checks must not hide failures.                                            |

Report failure, pending, skip, advisory and manual status explicitly. Build budgets, application E2E, visual comparison and performance checks require admission by the current policy and actual execution. Operator recovery and any additional CodeQL/mutation workflow need their own authorized evidence; a source helper alone proves neither deployment nor recovery. Use [validation](validation.md), [Storybook scope](storybook-verification.md) and [comprehension evaluation](comprehension-evaluation.md); do not substitute historical or another repository's evidence for a current-head result.
