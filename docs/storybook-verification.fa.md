# اعتبارسنجی Storybook

[English](storybook-verification.md) · [فارسی](storybook-verification.fa.md)

مرحلهٔ `storybook-verification` یک محیط جداگانهٔ نمایش و آزمون مؤلفه به ماژول‌های
منتشرشدهٔ رابط کاربری، Core، احراز هویت و صفحه‌های مدیریتی اضافه می‌کند. مقدار
`applicationReady: false` آگاهانه حفظ می‌شود؛ نقطهٔ ورود برنامه یا درخت متصل App و
Routes نداریم. ساخت ایستای این محیط و تعامل مؤلفه در Chromium، شاهد ساخت پنل محصول،
مسیر سرتاسری کامل برنامه، اتصال API عملیاتی، مقایسهٔ تصویری یا کارایی کاربران نیست.

## مالکیت دادهٔ ساختگی

[پیش‌نمایش](../.storybook/preview.tsx) تمام ماژول‌های مالک API حساب، احراز هویت، تقویم،
نقش‌ها، تنظیمات، بارگذاری و کاربران و همچنین کلاینت مشترک HTTP را با automock کامل
جایگزین می‌کند. این mockها اجرای واقعی را فراخوانی نمی‌کنند و حالت spy با عبور به
پیاده‌سازی اصلی ندارند. [mockها](../.storybook/mocks.ts) پیش از هر story، رکوردهای
ساختگی و تمام فراخوان‌های تنظیم‌شده را بازنشانی می‌کنند. هر story می‌تواند پاسخ را
برای نمایش بارگذاری، خطا، تلاش دوباره، لغو یا رفتار مجوز تغییر دهد. فایل محیطی،
اطلاعات دسترسی، وضعیت مرورگر، رکورد API یا بارگذاری واقعی را نخوانید.

درخواست تنظیم‌نشدهٔ کلاینت مشترک خطا می‌دهد و در
[نگهبان درخواست](../.storybook/request-guard.ts) ثبت می‌شود. راه‌انداز آزمون مرورگر
پس از هر story، درخواست‌های ثبت‌شده را بررسی می‌کند؛ بنابراین گرفتن خطا در مؤلفه
نمی‌تواند فراخوان اعلام‌نشده را بی‌صدا موفق نشان دهد. این نگهبان کلاینت HTTP مشترک
را پوشش می‌دهد و ادعای مسدودکردن تمام شبکهٔ مرورگر ندارد. فراخوان قابلیت‌ها باید
پشت mockهای صریح مالکان بماند.

[تنظیم مستقل Vite](../.storybook/vite.config.ts) کشف فایل محیطی و کشف خودکار پوشهٔ
عمومی ریشه را غیرفعال می‌کند، مقادیر ساختگی API و انتشار و مقصد خالی گزارش اختیاری
را می‌گذارد و `@` را در همین پروژه حل می‌کند. Storybook صریحاً این تنظیم را مصرف
می‌کند و تنظیم منتشرنشدهٔ Vite برنامه را بارگذاری نمی‌کند. پوشهٔ ایستای اعلام‌شده
دارایی‌های محلی منتشرشده را دارد. نقطهٔ ورود محصول لازم نیست.

## دادهٔ صریح زبان و ظاهر

نوار ابزار زبان، شیء کامل فرادادهٔ ساختگی API انگلیسی یا فارسی را از
[داده‌های نمونه](../src/test/storybook/fixtures.ts) انتخاب می‌کند؛ کد، جهت، تقویم و
هر دو نام در آن حاضرند. نوار ابزار مستقل جهت فقط جهت همان دادهٔ آزمایشی را تغییر
می‌دهد و نوار پوسته روشن یا تیره را انتخاب می‌کند. به این ترتیب زبان، جهت و پوسته
جداگانه آزموده می‌شوند، بدون آنکه فرادادهٔ محصول از کد حدس زده شود یا ترجیح زبان
بازدیدکننده ذخیره شود.

[PreviewFrame](../.storybook/PreviewFrame.tsx) و
[StoryShell](../src/test/storybook/StoryShell.tsx) راه‌اندازهای واقعی i18next، Day.js و
Ant Design، مشخصات سند و سطح نمایش مؤلفه را همگام می‌کنند. storyها از زمینهٔ ساختگی
Core، مسیر و حساب، همراه با کنترل واقعی Ant Design استفاده می‌کنند. انتخاب کنترل
در play با نام معنادار و موتور ترجمهٔ فعال انجام می‌شود؛ عنوان نقش و مجوز که سرور
ساختگی می‌دهد، دادهٔ صریح نمونه می‌ماند. هر ده کاتالوگ محصول کامل می‌مانند و API
مستقل همچنان مرجع تنظیمات محصول است.

## اعتبارسنجی الزامی

با نسخهٔ Node و npm همین مخزن اجرا کنید:

```sh
npm ci
npm run browser:install
npm run validate -- full
```

فرمان `browser:install` مرورگر Chromium مربوط به Playwright و وابستگی‌های لازم سیستم
را نصب می‌کند. CI این نصب را بعد از `npm ci` و قبل از اجرای بدون شرط گیت کامل مرجع
در همان کار `check` انجام می‌دهد.

[فهرست مرجع](../.agents/validation.json) یازده بررسی الزامی دارد: نه بررسی قبلیِ
فهرست فایل، سیاست CI، ممیزی، مرزها، تایپ، lint، قالب‌بندی، پوشش واحد و قواعد مخزن،
به‌علاوهٔ `build-storybook` و `test:storybook`. ساخت، خروجی ایستای واقعی را در
`coverage/storybook-static` می‌سازد.
[پروژهٔ مرورگر جداگانه](../vitest.storybook.config.ts) تمام storyهای ثبت‌شده و
assertionهای play آن‌ها را با Playwright در Chromium واقعی و بدون پنجره اجرا می‌کند.
تنظیم `a11y.test: "error"` باعث شکست اجرای مرورگر با نقض دسترس‌پذیری می‌شود؛ برای
موفق نشان دادن story، ممیزی را غیرفعال یا خطا را پنهان نکنید.

آستانه‌های واحد همان ۶۹٪ خط، ۶۸٪ دستور، ۵۹٪ تابع و ۵۴٪ شاخه می‌مانند و تمام
ماژول‌های محصول اندازه‌گیری می‌شوند. خروجی ساخت و نتیجهٔ مرورگر جای
`coverage/unit/lcov.info` یا `coverage/governance/lcov.info` را نمی‌گیرند؛ خروجی تولیدشده
کامیت نمی‌شود. نتیجهٔ واقعی همان نسخهٔ پیشنهادی را گزارش کنید؛ تنظیمات شاهد اجرا
نیستند. [Sonar](sonarqube.fa.md) و [مشارکت](../CONTRIBUTING.fa.md) را بخوانید.

پیش از ادغام پنل قابل اجرا، ترکیب واقعی برنامه را اضافه و گیت مرجع را به هر نوزده
بررسی واقعی برنامه، از جمله ساخت محصول، E2E کامل و کارهای تصویری گسترش دهید. نتیجه
را مشاهده و طبق [حفاظت شاخه](branch-protection.fa.md) بررسی‌های آن را الزامی کنید.
