# عملیات نسخه و بازگشت

[English](release-operations.md) · [فارسی](release-operations.fa.md)

برای تشخیص ابزارهای مجاز نسخه و بررسی برنامه، [سیاست انتشار](../.github/bootstrap-policy.json)، [فهرست سورس](bootstrap.fa.md) و [گیت مرجع](../.agents/validation.json) همان revision را بخوانید. مجازبودن سورس، ساخت اجراشده و استقرار، ادعاهای مستقل هستند. شاهد واقعی هرکدام را جدا ثبت کنید؛ هیچ اعلام سورسی مجوز اتصال به مقصد واقعی نیست.

برای انتشار دارای مجوز، revision دقیق، وابستگی‌های قفل‌شده، origin عمومی API، مسیر پایه و شناسهٔ تغییرناپذیر را ثبت کنید. با همان هویت بسازید، فرادادهٔ خروجی را بررسی و فقط یک‌بار در خروجی تازه بسته‌بندی کنید. artifact و hashها را نگه دارید؛ fixture ساختگی یا فایل تنظیمات، نسخهٔ منتشرشده نیست.

پوشهٔ نسخهٔ تازهٔ متعلق به اپراتور یا تگ دقیق image آماده کنید. پیش از تغییر اتمی، Nginx و TLS و نسخهٔ مقصد را بررسی و پس از آن readiness و smoke دارای مجوز را اجرا کنید. برای بازگشت، artifact سازگار و قبلاً تأییدشده را انتخاب و بعد از تغییر، شناسه را دوباره بسنجید. تنظیمات عمومیِ تغییریافته را با شناسهٔ قدیمی دوباره نسازید. artifact ناموفق و نخستین خطا را برای بررسی حفظ کنید.

بازگشت فرانت‌اند migration یا دادهٔ API را برنمی‌گرداند. این مخزن پایگاه داده یا upload سرور ندارد. سازگاری API و عملیات داده باید نزد مالک مستقل آن بماند. بدون مجوز صریح به مقصد واقعی متصل نشوید و میزبانی را تغییر ندهید.

[استقرار](deployment.fa.md)، [آماده‌سازی نسخه](releasing.fa.md) و [بازیابی](backup-restore.fa.md) را بخوانید.
