# فراهم‌کننده‌های هسته و پوستهٔ احراز هویت

[English](core-auth.md) · [فارسی](core-auth.fa.md)

انتشار `core-auth` فراهم‌کننده‌های Core و Ant Design، فرادادهٔ دسترسی و پیمایش،
فرم‌های ورود، ثبت‌نام و بازیابی گذرواژه و چیدمان‌های احراز هویت و پیش‌فرض را به
زیرساخت HTTP و رابط کاربری اضافه می‌کند. مقدار `applicationReady: false` باقی
می‌ماند: نقطهٔ ورود برنامه، درخت مسیرهای متصل یا پنل قابل اجرا وجود ندارد.
[مرحلهٔ بعدی صفحه‌های مدیریتی](business-screens.fa.md) ماژول مقصدها را اضافه می‌کند؛
اتصال مسیرهای برنامه همچنان کار آینده است.

## مالکیت فراهم‌کننده‌ها و ترجیحات

`CoreProvider` تنظیمات اعتبارسنجی‌شدهٔ برنامه را با چرخهٔ مشترک خواندن دریافت
می‌کند. آغاز کار با فرادادهٔ فارسی است؛ تنظیمات قابل استفاده هنگام تازه‌سازی حفظ
می‌شوند، تلاش دوباره ممکن است و تمرکز دوباره بر پنجره باعث تازه‌سازی می‌شود.
پذیرش نسخهٔ ذخیره‌شدهٔ تنظیمات، خواندن قدیمی‌تر را کنار می‌زند. خواندن لغوشده یا
منسوخ نمی‌تواند تنظیمات فعلی را بازنویسی کند. `SettingsFeedback` وضعیت بارگذاری،
شکست و تلاش دوباره را برای اتصال آیندهٔ برنامه در دسترس قرار می‌دهد.
وقتی بازنمایش نامرتبط والد وضعیت را عوض نمی‌کند، مقدار context و callbackهای Core
پایدار می‌مانند. تغییر واقعی تنظیمات و ظاهر همچنان به مصرف‌کننده‌های context می‌رسد.

API مالک زبان فعال، جهت، تقویم، نام‌ها، نشان‌ها و پالت‌ها است. Core همین فرادادهٔ
اعتبارسنجی‌شده را به i18next، Day.js و `AntdProvider` می‌دهد؛ سازگارکنندهٔ Ant
Design هر ده زبان ثبت‌شدهٔ کتابخانه را فراهم می‌کند و زبان و جهت سند را به‌روز
می‌کند. ظاهر از قرارداد خالص مشترک مشتق می‌شود. فقط پوسته و حالت فشرده ترجیح
مرورگر هستند و با رویداد ذخیره‌سازی همگام می‌شوند. ترجیح زبان بازدیدکننده نداریم.
[بومی‌سازی](localization.fa.md) و [زیرساخت رابط کاربری](ui-foundation.fa.md) را ببینید.

`useCore` و `useAntd` به فراهم‌کنندهٔ متناظر خود نیاز دارند. برنامهٔ آینده باید
Core را بیرون Ant Design قرار دهد و فرم‌ها و چیدمان‌ها را داخل مسیریاب نصب کند.
این مرحله ماژول‌ها را با درخت‌های صریح و مصنوعی فراهم‌کننده و مسیریاب آزمایش
می‌کند و راه‌اندازی محیط واقعی را اضافه نمی‌کند.

## مالکیت نشست و دسترسی

چیدمان پیش‌فرض حساب فعلی را می‌خواند، بازخورد بارگذاری و تلاش دوباره نشان می‌دهد
و پیمایش را از مجوزهای حساب می‌سازد. ابزارهای مجوز عمل مسیر از همان واژگان مجوز و
قاعدهٔ مدیر سامانه استفاده می‌کنند. این بررسی‌ها نمایش را کنترل می‌کنند؛ API
جداگانه باید هر عملیات حفاظت‌شده را مجاز بشمارد.
انتخاب گزینهٔ پیمایش در موبایل، حتی مسیر فعلی، کشوی منو را می‌بندد. صفحهٔ پیدا‌نشدن
مسیر یک دکمهٔ بازگشت به خانه دارد که با صفحه‌کلید نیز کار می‌کند.

ورود به چیدمان احراز هویت، نشست قبلی سمت کاربر را نامعتبر می‌کند. خروج، عملیات
در جریان نسل فعلی توکن را مشترک می‌کند. چیدمان پیش‌فرض پس از خروج، حتی خروج
ناموفق، وضعیت کاربر را پاک می‌کند؛ تکمیل قدیمی نمی‌تواند ورود جدیدتری را پاک کند.
لایهٔ مشترک HTTP همچنان مالک تازه‌سازی توکن، رسیدگی به دسترسی نامعتبر و بررسی
نسل است. پاک‌سازی سمت کاربر به‌تنهایی ابطال نشست سرور را اثبات نمی‌کند؛
[مالکیت HTTP](http-client.fa.md) و [فهرست بازبینی احراز هویت](security/authentication-review.fa.md)
را ببینید.

## چرخهٔ درخواست فرم‌ها

ورود، ثبت‌نام، درخواست رمز یک‌بارمصرف و بازیابی گذرواژه در مرز HTTP ویژگی،
`AbortSignal` اختیاری می‌پذیرند. فرم‌ها هنگام جداشدن از درخت نمایش، عملیات معلق
خود را لغو می‌کنند. تغییر شمارهٔ همراه، درخواست قدیمی رمز را لغو و رمز و زمان
انتظار قدیمی را پیش از درخواست جدید پاک می‌کند. نگهبان عملیات معلق، قصد درخواست
را پیش از اعتبارسنجی ناهمگام فیلد شماره ثبت می‌کند. خطای اعتبارسنجی کنار فیلد
می‌ماند؛ کار لغوشده پیام خطای عمومی یا هدایت دیرهنگام ایجاد نمی‌کند.
ثبت‌نام و بازیابی گذرواژه چرخهٔ متعلق به دامنهٔ `useOtpRequest` را برای اعتبارسنجی،
لغو، پاک‌سازی شمارهٔ قبلی و شمارش زمان انتظار مشترک دارند. هر فرم عملیات ارسال خود
را نگه می‌دارد و ارسال ناهمگام را صریحاً به callback بدون مقدار بازگشتی فرم متصل
می‌کند؛ Promise به‌جای نتیجهٔ همگام مصرف نمی‌شود.
دکمهٔ ارسال ثبت‌نام و بازیابی گذرواژه داخل فرم و از نوع submit است؛ Enter و فعال‌کردن
دکمه از اعتبارسنجی و نگهبان درخواست تکراری یکسان استفاده می‌کنند. درخواست رمز
یک‌بارمصرف همچنان عمل جداگانهٔ دکمه است.

ورود و ثبت‌نام علاوه بر نگهبان موجود نسل نشست، پس از تکمیل انتقال و پیش از ذخیرهٔ
توکن دسترسی، لغو را بررسی می‌کنند. بنابراین پاسخ تکمیل‌شده نمی‌تواند پس از ترک
صفحه توکن نصب کند. لغو از ادامهٔ عملیات و وضعیت سمت کاربر محافظت می‌کند؛ اثر
تغییر سرور یا کوکی پذیرفته‌شدهٔ مرورگر را برنمی‌گرداند. نشانی و بدنهٔ درخواست‌ها
تغییر نکرده‌اند. [اعتمادپذیری درخواست](admin-request-reliability.fa.md) را ببینید.

## شواهد و فعال‌سازی آینده

آزمون‌های واقعی React و Ant Design در jsdom، جایگزینی تنظیمات Core، تمرکز و تلاش
دوباره، فرادادهٔ دقیق زبان، رفتار حساب و پیمایش و چیدمان و اعتبارسنجی و لغو فرم
را بررسی می‌کنند. آزمون‌های انتقال مصنوعی Axios و MSW لغو چهار عملیات احراز هویت
را می‌سنجند؛ آزمون جداگانهٔ پاسخ تکمیل‌شده بررسی می‌کند که ورود یا ثبت‌نام لغوشده
توکن نصب نکند. آزمون‌های بازگشت برای رقابت توکن، هدایت دیرهنگام ورود و بازخورد
شمارهٔ نامعتبر، در برابر رفتار قبلی شکست می‌خورند.

[دروازهٔ رسمی نه‌بررسی این مرحله](../.agents/validation.json) همهٔ ماژول‌های محصول
منتشرشده را اندازه می‌گیرد. بررسی نوع، قالب، lint، وابستگی و مرزها و پوشش واقعی
آزمون واحد و راهبری در آن حضور دارند. این آزمون‌ها رفتار اعلام‌شدهٔ ماژول‌ها را
می‌سنجند؛ اتصال واقعی API، ساخت محصول، مسیرهای مرورگر، بارگذاری قلم یا نتیجهٔ
بصری را اثبات نمی‌کنند. انتشار قابل اجرای آینده باید دروازهٔ کامل را به هر نوزده
بررسی واقعی برنامه گسترش دهد و پیش از ادغام، موفقیت کارهای الزامی ساخت، مرورگر و
بصری را مشاهده کند.

برای مرزهای نگهداری و قواعد تحویل، [معماری](architecture.fa.md)،
[محدودهٔ آغازین](bootstrap.fa.md) و [مشارکت](../CONTRIBUTING.fa.md) را ببینید.
