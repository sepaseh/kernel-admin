# Assistant-neutral comprehension foundation

[English](ai-code-understanding.md) · [فارسی](ai-code-understanding.fa.md)

The `assistant-guidance` phase publishes canonical English rules and skills, the AGENTS entry point, a machine task map, validation/settings/CI consistency checks with regressions, source-linked decisions and a read-only evaluation procedure. Human guides have complete English/Persian companions; active assistant instructions and evaluation prompts are English only. No AI runtime, vector database, indexer or cloud dependency is added to the application.

The product remains a non-runnable component workshop with `applicationReady: false`. Navigation points to current providers, HTTP/lifecycle owners, flat local catalogs, forms, layouts, widgets and synthetic Storybook evidence. App/Routes composition, full application E2E, deployment and visual/performance tooling remain future work.

Use targeted search and owning source, contracts and tests. Static maps cannot establish permissions, runtime session state or transactional behavior. A passing consistency check does not prove that a host loaded instructions, that an assistant understood them, or that guidance improved performance. Keep the source revision, unpublished-source fingerprint and uncertainty visible.

Optional Node/Bash hooks and host adapters require actual host support. They are development aids, not runtime dependencies or an authorization boundary. User instructions and existing authorization govern the task. Search/graph tools require a concrete need, access and measured benefit. Use the [evaluation procedure](comprehension-evaluation.md) and record actual results; configured scenarios are not completed experiments.
