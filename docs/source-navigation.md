Extend the machine task map as additional source owners are published. Read the files and assertions before claiming behavior. Existing configuration, test filenames and optional hooks do not prove execution, provider approval or automatic assistant loading.

The [CodeQL security workflow](../.github/workflows/codeql.yml) is validated by the CI policy checker and its regressions. Its native security result remains separate from scanner execution; see [hosted checks and review](validation.md#hosted-checks-and-review).

The [actionlint runner](../scripts/run-actionlint.mjs) and [its regressions](../scripts/run-actionlint.test.mjs) own pinned workflow syntax and expression validation. The application gate runs it once through the manifest.

The `application-verification` workflow resolves the tested source in `scope`, runs the manifest profile once in the required `check` and imports verified coverage in the scanner job. Use the [CI policy and evidence owner](../scripts/check-ci.mjs), [its regressions](../scripts/check-ci.test.mjs) and [validation](validation.md) when changing evidence publication or Sonar handoff. Use the [visual runner](../scripts/run-visual.mjs) and [reviewed baseline metadata](../e2e/visual/baselines/application/win32/metadata.json) for image comparison.
