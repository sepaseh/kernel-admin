# بازیابی artifact ایستا

[English](backup-restore.md) · [فارسی](backup-restore.fa.md)

این متن روش آیندهٔ اپراتور است، نه گزارش بازیابی اجراشده. مرحلهٔ فعلیِ غیرقابل‌اجرا فقط پیش‌نیازهای بسته‌بندی و بازیابی و آزمون ساختگی را منتشر می‌کند.

پس از فعال‌سازی مجاز، artifact عمومیِ تغییرناپذیر، manifest نسخه، تنظیمات عمومی ساخت و منشأ تنظیمات تولیدشده را نگه دارید. گواهی و کلید باید با سیاست پشتیبان امن اپراتور، جدا از Git و آرشیو عمومی نسخه، حفظ شوند. revision، hash artifact، شناسهٔ نسخه، مسیر پایه و سازگاری API را ثبت کنید تا بازیابی همان artifact اصلی را انتخاب کند، نه ساخت دوبارهٔ بایت‌های متفاوت با شناسهٔ قدیمی.

بازیابی را در پوشهٔ نسخهٔ تازه و تأییدشده انجام دهید، تنظیمات و TLS را بسنجید، نسخه را اتمی فعال کنید و سپس HTML و شناسهٔ نسخه را در مقصد دارای مجوز بررسی کنید. تا تأیید بازیابی، نسخهٔ قبلیِ تأییدشده را حفظ و خطاها و نتیجهٔ پاک‌سازی را ثبت کنید. آزمون بسته‌بندی با fixture، بازیابی‌پذیری نسخهٔ پشتیبان واقعی را اثبات نمی‌کند.

این ادمین پایگاه داده یا مخزن upload سمت سرور ندارد. پشتیبان API، migration و بازگشت داده در اختیار مالک API مستقل است. هنگام بازیابی فرانت‌اند وضعیت آن را جابه‌جا یا reset نکنید. تنظیمات مرورگر و نامعتبرکردن نشست تابع قواعد کلاینت‌اند و نسخهٔ پشتیبان سرور نیستند.

[استقرار](deployment.fa.md) و [بازگشت نسخه](release-operations.fa.md) را ببینید.
