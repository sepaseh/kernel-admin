# قرارداد مصرف‌کنندهٔ HTTP و تأیید provider

[English](contract-testing.md) · [فارسی](contract-testing.fa.md)

شواهد فعلی مصرف‌کننده در مالک‌های API و نوع هر feature، آزمون transport مشترک و fixture ساختگی MSW با رد درخواست پیش‌بینی‌نشده قرار دارند. نوع‌های خالص transport در `src/shared/api` و محدودیت مشترک نام پروفایل در `src/shared/contracts` هستند. تبدیل wire به snake_case، اعتبارسنجی runtime پاسخ حساس توکن و تنظیمات، محدودیت درخواست و حفاظت نسل نشست را حفظ کنید.

API مستقل مالک اجرای endpoint، مجوز، احراز هویت، ذخیره‌سازی، پایگاه داده و migration و مجموعهٔ Bruno خود است. کاتالوگ ادمین محلی می‌ماند و تنظیمات اعتبارسنجی‌شدهٔ API مالک زبان، جهت، تقویم و نام‌هاست. موفقیت آزمون mock مصرف‌کننده، پیاده‌سازی قرارداد توسط provider واقعی را اثبات نمی‌کند. تغییر ناسازگار wire و برنامهٔ rollout را با مالک API هماهنگ کنید.

در مرحلهٔ بررسی برنامه، `contract/api.contract.test.ts` آداپتور واقعی کلاینت ادمین را مقابل mock provider محلی Pact که منحصراً تحت مالکیت آزمون است اجرا می‌کند. مصرف‌کننده `kernel-admin` و قرارداد provider برابر `kernel-api` است. موارد آزمون، ورود و تبدیل توکن، دادهٔ حساب احرازشده، شناسهٔ همبستگی درخواست هنگام خطای سرور، رد سیاست بازیابی و تعارض آخرین مدیر را پوشش می‌دهند. ورودی‌ها و اطلاعات ورود ساختگی‌اند؛ هیچ API یا حساب واقعی فراخوانی نمی‌شود.

سندهای تولیدشدهٔ Pact زیر `coverage/contract/pacts` قرار می‌گیرند. آن‌ها خروجی کد بررسی‌شده‌اند، نه ورودی نگه‌داری‌شدهٔ برنامه یا اثبات انطباق provider مستقل. آن‌ها را از فهرست کد و انتشار بیرون نگه دارید. `npm run test:contract` را مطابق [فهرست مرجع](../.agents/validation.json) اجرا کنید؛ موفقیت بررسی متمرکز مصرف‌کننده جای گیت کامل روی درخت دقیق را نمی‌گیرد.

تأیید provider همچنان متعلق به API مستقل است و به پیاده‌سازی واقعی آن، وضعیت‌های سازگار و مقصد صریحاً مجاز نیاز دارد. پیش از ادعای سازگاری، revision دقیق مصرف‌کننده و provider و نتیجهٔ مشاهده‌شده را ثبت کنید. تولید سند Pact یا موفقیت mock محلی چنین شاهدی فراهم نمی‌کند.

آزمون واحد و نوع مرتبط و [گیت کامل مرجع](validation.fa.md) را اجرا کنید. دامنهٔ آن‌ها همان کد منتشرشده است. [مالکیت HTTP](http-client.fa.md) و [پایداری درخواست](admin-request-reliability.fa.md) را ببینید.
