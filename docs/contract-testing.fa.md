# قرارداد HTTP و شواهد provider

[English](contract-testing.md) · [فارسی](contract-testing.fa.md)

شواهد فعلی مصرف‌کننده در مالک‌های API و نوع هر feature، آزمون transport مشترک و fixture ساختگی MSW با رد درخواست پیش‌بینی‌نشده قرار دارند. نوع‌های خالص transport در `src/shared/api` و محدودیت مشترک نام پروفایل در `src/shared/contracts` هستند. تبدیل میان داده‌های داخلی و قالب snake_case در wire، اعتبارسنجی runtime پاسخ حساس توکن و تنظیمات، محدودیت درخواست و حفاظت نسل نشست را حفظ کنید.

API مستقل مالک اجرای endpoint، مجوز، احراز هویت، ذخیره‌سازی، پایگاه داده و migration و مجموعهٔ Bruno خود است. کاتالوگ ادمین محلی می‌ماند و تنظیمات اعتبارسنجی‌شدهٔ API مالک زبان، جهت، تقویم و نام‌هاست. موفقیت آزمون mock مصرف‌کننده، پیاده‌سازی قرارداد توسط provider واقعی را اثبات نمی‌کند. تغییر ناسازگار wire و برنامهٔ rollout را با مالک API هماهنگ کنید.

با [سیاست انتشار](../.github/bootstrap-policy.json) و [فهرست اعتبارسنجی](../.agents/validation.json) مشخص کنید وابستگی Pact، فایل `contract/api.contract.test.ts` و فرمان قرارداد پذیرفته شده‌اند یا نه. در صورت پذیرش، از هویت مصرف‌کنندهٔ `kernel-admin`، معنای فعلی HTTP و سرور mock محلی با مالکیت انحصاری و دادهٔ ساختگی استفاده کنید. این آزمون واقعی مصرف‌کننده همچنان با تأیید جداگانه و دارای مجوز علیه provider مستقل API تفاوت دارد. تا وقتی `applicationReady` برابر false است، fixture مصرف‌کننده به‌تنهایی برنامهٔ قابل اجرا را اثبات نمی‌کند. حساب واقعی یا production نباید fixture باشد.

آزمون واحد و نوع مرتبط و [گیت کامل مرجع](validation.fa.md) را اجرا کنید. دامنهٔ آن‌ها همان کد منتشرشده است. [مالکیت HTTP](http-client.fa.md) و [پایداری درخواست](admin-request-reliability.fa.md) را ببینید.
