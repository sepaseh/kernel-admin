# آماده‌سازی میزبانی ایستا

[English](deployment.md) · [فارسی](deployment.fa.md)

مرحلهٔ فعلی `assistant-guidance` عمداً پیش‌نیازهای محدود استقرار و کیفیت را اضافه می‌کند، اما `applicationReady: false` باقی می‌ماند. الگوها، اعتبارسنج‌ها، ابزارهای بسته‌بندی و آزمون‌های ساختگی موجودند؛ ورودی برنامه، ساخت production، اجرای واقعی Docker و بررسی محیط مستقر هنوز شاهد فعلی نیستند.

[اعتبارسنج تنظیمات عمومی](../scripts/validate-deployment-env.mjs) origin دقیق API، مسیر پایهٔ امن با اسلش پایانی، شناسهٔ تغییرناپذیر نسخه و URL اختیاری مشاهده‌پذیری را بررسی می‌کند. به‌جز HTTP صریح روی loopback، HTTPS لازم است. این مقادیر در مرورگر قابل مشاهده‌اند و نباید اطلاعات ورود داشته باشند. API مستقل باید خودش درخواست را مجاز کند و origin واقعی ادمین را بپذیرد.

[تولید تنظیمات](../scripts/render-deployment.mjs) الگو و شیء تنظیمات صریح می‌گیرد، مقدار رشته‌ای و معتبر `ADMIN_HOST` را به حروف کوچک تبدیل می‌کند، میزبان خالص DNS و پورت و مسیر را می‌سنجد و فقط placeholderهای عمومیِ تعریف‌شده را جای‌گذاری می‌کند. CLI با گزینه‌های `--template`، `--config-file` و `--output` فقط مسیرهای نسبی درون پوشهٔ کاری را می‌پذیرد، خروج از این مرز و پیوندهای نمادین را رد می‌کند، فایل‌های معمولیِ انتخاب‌شده را می‌خواند و خروجی تازه را بدون بازنویسی می‌سازد. نام `--config-file` مانع پیش‌بارگذاری Node با گزینهٔ `--env-file` می‌شود تا مسیر پیش از خواندن تنظیمات اعتبارسنجی شود. هنگام بررسی کد آن را روی فایل واقعی اپراتور اجرا نکنید. سه مسیر نمونهٔ عمومیِ بازبینی‌شده ساختگی‌اند؛ سایر فایل‌های محیطی همچنان خصوصی هستند.

[بسته‌بندی](../scripts/package-release.mjs) به پوشهٔ کامل `dist` و فرادادهٔ منطبق ساخت نیاز دارد. شناسه، مسیر پایه و origin و مرز مسیرها را می‌سنجد، asset پیوندی و خروجی نسخهٔ موجود را رد می‌کند و نام‌های ممنوع را کنار می‌گذارد. fixtureهای ساختگی این قواعد را بررسی می‌کنند؛ آن‌ها artifact تولیدی یا ممیزی محتوای محرمانه نیستند.

فعال‌سازی آیندهٔ دارای مجوز باید ابتدا ساخت برنامه و گیت واقعی مرورگر و تصویر را منتشر و اعتبارسنجی کند. سپس یک شناسهٔ تغییرناپذیر بسته‌بندی، تنظیمات تازهٔ Nginx تولید، TLS به‌صورت خصوصی تهیه و میزبان مقصد بررسی شود؛ فقط نسخهٔ تأییدشده فعال شود. Docker و Compose نیز به همان ساخت آینده وابسته‌اند. فرایند Nginx آن با کاربر غیرممتاز و پورت‌های داخلی ۸۰۸۰ و ۸۴۴۳ اجرا می‌شود؛ همهٔ قابلیت‌های لینوکس حذف و نوشتن به `/tmp` محدود است. مالکیت خواندنی کلید TLS را بیرون image فراهم و آن را فقط‌خواندنی mount کنید. [ابزار بررسی سلامت](../scripts/healthcheck.mjs) شبکه را فقط روی مقصد دارای مجوز صریح اجرا کنید. این متن نتیجهٔ استقرار، DNS، TLS یا دسترس‌پذیری را اعلام نمی‌کند.

CLI ابزار سلامت آرگومان‌های `TARGET_URL [EXPECTED_RELEASE [BASE_PATH]]` را می‌پذیرد و تابع آن نیز همین سه آرگومان را دارد. با حذف مقصد، مقدار `http://127.0.0.1/` حفظ می‌شود؛ مقدار صریح `null` نامعتبر است. شناسهٔ نسخهٔ مورد انتظار اگر صریحاً رشتهٔ خالی باشد، پیش از هر درخواست رد می‌شود. مقصد باید HTTP(S) و بدون اطلاعات ورود، query یا fragment باشد. بررسی صرفاً HTML می‌تواند یک مسیر داخلی را هدف بگیرد. با شناسهٔ نسخهٔ مورد انتظار و بدون مسیر پایهٔ صریح، مقصد باید URL پایهٔ برنامه با اسلش پایانی و ساختار استاندارد را اعلام کند؛ ابزار مسیر پایه را از یک مسیر دلخواه SPA حدس نمی‌زند. برای بررسی مسیر داخلی، پایهٔ تنظیم‌شده را بدهید: مقصد `/console/auth/` یا `/console/auth/register` همراه پایهٔ `/console/` ابتدا سند و سپس `/console/_kernel/release` را روی همان origin درخواست می‌کند. پایهٔ تو‌در‌تو مانند `/team/admin/` نیز همین رفتار را دارد. پایه باید `/` یا بخش‌های استاندارد جداشده با اسلش و دارای اسلش پایانی باشد و مسیر مقصد درون همان پایه بماند. مقصد یا پایهٔ نامعتبر پیش از هر درخواست شبکه رد می‌شود؛ redirect همچنان خطا است.
