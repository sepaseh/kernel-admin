# سیاست حفاظت شاخه

[English](branch-protection.md) · [فارسی](branch-protection.fa.md)

مرحلهٔ واقعی، `applicationReady` و نقش اعتبارسنجی را از [سیاست انتشار](../.github/bootstrap-policy.json) و [فهرست مرجع](../.agents/validation.json) بخوانید. Workflow تک‌اجرای مشترک، آمادگی برنامه را تغییر نمی‌دهد و حفاظت راه‌دور را نصب نمی‌کند. مدیران مخزن تنظیمات واقعی را مدیریت می‌کنند.

نتیجهٔ موفق بررسی الزامی CI و سرویس برای منبع فعلی، حداقل یک تأیید بازبینی و حل گفت‌وگوها لازم است. حفاظت باید شامل مدیران باشد، تأیید قدیمی را کنار بگذارد، شاخهٔ به‌روز و تاریخچهٔ خطی را لازم کند و ارسال اجباری و حذف شاخه را ممنوع کند. پنج نتیجهٔ بومی و شناسهٔ مشاهده‌شدهٔ برنامهٔ GitHub را حفظ کنید:

| نتیجهٔ الزامی              | ارائه‌دهنده    | شناسهٔ برنامه |
| -------------------------- | -------------- | ------------- |
| `check`                    | GitHub Actions | `15368`       |
| `PR file limit`            | GitHub Actions | `15368`       |
| `SonarQube Cloud analysis` | GitHub Actions | `15368`       |
| `SonarCloud Code Analysis` | SonarCloud     | `12526`       |
| `CodeRabbit`               | CodeRabbit     | `347564`      |

کار واقعی `check` مالک پروفایل الزامیِ فعلی است. با آمادگی false، ماژول‌ها و محیط مستقل Storybook را بررسی می‌کند و ساخت پنل کامل، E2E برنامه یا تصویر فعلی را فراهم نمی‌کند. با آمادگی true، بررسی پذیرفته‌شدهٔ برنامه و تصویر تأییدشدهٔ مرتبط اجرا می‌شود و سازگاری کامل مرورگر نقش زمان‌بندی‌شده و دستی پیش از انتشار دارد. درخواست کامل با آمادگی false، همچنان به پروفایل فعلی محدود است. برای ساخت نتیجهٔ بیشتر، مجموعهٔ تکراری اضافه نکنید و کار اجرا‌نشده را اجرای واقعی ننامید.

کار بررسیِ محافظت‌شده در هر رویداد مرتبط اجرا می‌شود. ویرایش صرف عنوان یا توضیح PR فقط زمانی می‌تواند پوشش اندازه‌گیری‌شدهٔ اصلی را بازاستفاده کند که آخرین اجرای پیشین CI واقعاً برای همان head و مبنای مقصد و commit و درخت بررسی‌شده موفق بوده و هویت تولیدکننده و اجرای اصلی و چکیدهٔ هر دو LCOV تأیید شود. نبود یا ناهماهنگی شاهد، اجرای کامل تازه را لازم می‌کند. کار اجرا‌نشده اجرای موفق نیست و تغییر مبنا استفادهٔ مجدد را نامعتبر می‌کند. سپس کار واقعی **SonarQube Cloud analysis**، همان منبع تأییدشده را با این گزارش‌ها و بدون تکرار مجموعه تحلیل می‌کند.

پیش از درخواست دستی مجاز CodeRabbit، [پیش‌بررسی درخواست](../CONTRIBUTING.fa.md#پیش-از-درخواست-coderabbit) را کامل کنید. همهٔ بررسی‌های مرتبط و الزامیِ غیر CodeRabbit، scanner واقعی و دروازهٔ کیفیت غیرهم‌زمان Sonar باید برای منبع بررسی‌شده موفق باشند. همهٔ صفحه‌ها و شدت‌های گزارش مرتبط، شامل کد قبلی، باید صفر مسئلهٔ باز یا حل‌نشده داشته باشند. دروازهٔ سبز، مثبت کاذب مستندشده‌ای که هنوز در سرویس باز است یا بررسی پیشرفتِ اجرا‌نشده، آمادگی را ثابت نمی‌کند. منبع یا مبنای جدید، شاهد قبلی را نامعتبر می‌کند. سهمیهٔ واقعی سرویس رعایت و درخواست هم‌زمان تکراری حذف شود.

بازبینی خودکار CodeRabbit غیرفعال است. وضعیت اجرا‌نشده تأیید نیست؛ بازبینی کامل واقعی و شمار تأیید بومی لازم است. GitHub می‌تواند بررسی افراد واجد شرایط دیگر را هم بشمارد و هویت ربات خاصی را الزام نمی‌کند. fixture منبع و موفقیت محلی، سازگاری API مستقل، بازبینی انسانی تصویر یا استقرار را ثابت نمی‌کند. تغییر حفاظت راه‌دور همچنان مجوز و تأیید میزبانی‌شده لازم دارد.

[راه‌اندازی Sonar](sonarqube.fa.md)، [اعتبارسنجی](validation.fa.md) و [مشارکت](../CONTRIBUTING.fa.md) را ببینید. نقش گزارش‌دهندهٔ کارایی به مالک و موعد واقعی فهرست پذیرفته‌شده محدود است و جدا از ممیزی موفق گزارش می‌شود.
