# سیاست حفاظت شاخه

[English](branch-protection.md) · [فارسی](branch-protection.fa.md)

سورس application-verification علاوه بر همهٔ بررسی‌های قبلی، job واقعی native با نام build، e2e و visual را می‌پذیرد. تنظیم سورس اثبات نصب حفاظت راه دور یا اجرای آن jobها نیست. پیش از ادغام برنامه، مجوز تغییر مرحلهٔ حفاظت را بگیرید، موفقیت واقعی jobهای head جاری را ببینید و تنظیمات زنده را تأیید کنید.

contextهای native قبلی و هویت سرویس مشاهده‌شده حفظ می‌شوند:

| context                  | سرویس          | App ID |
| ------------------------ | -------------- | ------ |
| check                    | GitHub Actions | 15368  |
| PR file limit            | GitHub Actions | 15368  |
| SonarQube Cloud analysis | GitHub Actions | 15368  |
| SonarCloud Code Analysis | SonarCloud     | 12526  |
| CodeRabbit               | CodeRabbit     | 347564 |

سیاست هدف ادغام برنامه همچنین contextهای native با نام build، e2e و visual از GitHub Actions با App15368 را پس از مشاهدهٔ اجرای واقعی روی پلتفرم منطبق لازم می‌داند. حداقل یک تأیید بازبینی، مکالمات حل‌شده، اعمال حفاظت برای مدیر، ابطال تأیید قدیمی، الزام شاخهٔ به‌روز، تاریخ خطی و منع force push/حذف حفظ می‌شود. تنظیم راه دور را بی‌مجوز عوض نکنید و job نمایشی/skipped به کار نبرید.

هر job با نام check، [پروفایل کامل مرجع](../.agents/validation.json) را همراه ساخت واقعی برنامه، مرورگر/تصویر و کارایی اجرا می‌کند. job اختصاصی برنامه، شاهد مستقل الزامی می‌افزاید. fixture مرورگر ساختگی است و تأیید API-provider نیست. بررسی تصویری منشأ دقیق محیط/سورس و تأیید انسانی واقعی هر تصویر تازه را لازم دارد؛ دارایی تاریخی جای این تأیید را نمی‌گیرد.

بازبینی خودکار CodeRabbit غیرفعال می‌ماند. پیش از یک درخواست دستی مجاز، [preflight آخرین head](../CONTRIBUTING.fa.md) را انجام دهید: تمام بررسی‌های محافظت‌شدهٔ غیر CodeRabbit، اجرای scanner و دروازهٔ ناهم‌زمان Sonar همان head باید موفق باشند و تمام صفحه‌های گزارش کامل، در همهٔ شدت‌ها و کد قبلی/جدید، صفر مسئلهٔ حل‌نشده داشته باشند. شاهد مفقود، pending، failed، skipped یا قدیمی مانع درخواست است. commit جدید preflight را باطل می‌کند. false positive مستندِ باز همچنان مانع است؛ اصلاح واقعی/تحلیل تازه یا طبقه‌بندی مجاز سرویس لازم است، نه بررسی ضعیف‌تر.

ظرفیت واقعی را رعایت و درخواست پذیرفته‌شده/درحال‌اجرای تکراری نفرستید. پردازش و تأیید واقعی را بررسی کنید، نه status موفقِ skipped یا پاسخ محدودیت ظرفیت. CodeRabbit فقط برای حذف چرخه از preflight کنار گذاشته می‌شود و شرط ادغام باقی می‌ماند. شمارش native تأیید، بازبین واجد شرایط دیگر را هم می‌پذیرد و هویت bot خاص را تحمیل نمی‌کند. اجرای scanner با دروازهٔ واقعی کیفیت سرویس جداست. [Sonar](sonarqube.fa.md)، [مشارکت](../CONTRIBUTING.fa.md) و [اعتبارسنجی](validation.fa.md) را بخوانید.
