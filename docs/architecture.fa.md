# معماری پنل

[English](architecture.md) · [فارسی](architecture.fa.md)

به‌روزرسانی محدوده: ۲۷ اکتبر ۲۰۲۶. مرحلهٔ منتشرشدهٔ `core-auth` مقدار
`applicationReady: false` دارد. این مرحله سورس مستقل React با Ant Design/antd-style،
React Router و Axios، ارائه‌دهنده‌های Core و Ant Design، فرم‌های احراز هویت،
ماژول‌های چیدمان و فرادادهٔ تایپ‌شدهٔ دسترسی و راهبری را ارائه می‌کند. نقطهٔ ورود
برنامه، ترکیب App و Routes، رابط صفحه‌های کسب‌وکار، ساخت نهایی و مسیر مرورگر وجود
ندارد. تست ماژول و jsdom ساختگی، پنل قابل اجرای React/Vite را ثابت نمی‌کند.

هر قابلیت مالک نوع HTTP، مسیر و ابزار منتشرشدهٔ خود است. فرم احراز هویت مالک
auth را فراخوانی می‌کند؛ چیدمان اصلی مالک account را می‌خواند و نوع کلید مجوز
متعلق به roles است. ماژول مالک موجود را وارد کنید و به ورودی منتشرنشده تکیه
نکنید. `src/shared/api` مالک زیرساخت انتقال و نشست و نوع‌های آن است.
`src/shared/contracts` محدودیت مشترک نام پروفایل و واژگان خالص ظاهر را نگه می‌دارد.
shared مستقل از app و features و layouts می‌ماند. alias فرانت‌اند در `src` حل
می‌شود؛ checkout دیگر، انتشار بستهٔ داخلی یا SDK بک‌اند وابستگی سورس نیست.

در `src/shared/i18n` برای هر زبان یک کاتالوگ کامل، تخت و هم‌نام کد آن وجود دارد.
`catalogs.ts` اشیا را ثبت و `index.ts` ترجمه را راه‌اندازی می‌کند. ترجیحات سراسری
پوسته و فشردگی، ساخت پوسته، هوک درخواست و رابط قابل استفادهٔ مجدد در shared
می‌مانند. لایهٔ app مالک context و ارائه‌دهنده‌های Core و فرادادهٔ راهبری است؛
layouts رفتار پوستهٔ صفحه و بررسی حساب را مدیریت می‌کند.
[Core و احراز هویت](core-auth.fa.md) این مالکان منتشرشده و محدودیتشان را توضیح می‌دهد.

API مستقل مالک اجرای احراز هویت، مجوزدهی، پایگاه داده، migration و ذخیره‌سازی است.
پنل آن را از HTTP مصرف می‌کند؛ منو ابزار راحتی است و جای مجوزدهی نیست. اعتبارنامهٔ
bearer فقط در حافظه می‌ماند؛ refresh مشترک، تکرار محدود و نسل درخواست از ورود
تازه محافظت می‌کند. signal اختیاری احراز هویت نیز مانع ثبت توکن پاسخ ورود یا
ثبت‌نام لغوشده می‌شود. لغو نمی‌تواند تغییر ثبت‌شدهٔ سرور یا اثر کوکی را برگرداند.
ابطال نشست سرور کار API است.

وب‌سایت عمومی مصرف‌کننده‌ای جدا با سورس و روند انتشار مستقل است. این نسخهٔ پنل
پیاده‌سازی، استقرار یا نتیجهٔ امنیتی API و وب‌سایت را تازه بررسی نمی‌کند. تغییر
ناسازگار قرارداد و ترتیب انتشار را با مالکان آن‌ها هماهنگ و هر مخزن را جدا بررسی کنید.

زبان فعال متعلق به تنظیم عمومی API است و تغییرش به مجوز مدیر کل در API نیاز دارد.
Core تنظیمات را هنگام mount و بازگشت focus می‌خواند. کد، جهت، تقویم و نام‌های
اعتبارسنجی‌شده را یکجا نگه می‌دارد؛ i18next و Day.js از آن‌ها پیروی می‌کنند و Ant
Design زبان کتابخانه و زبان و جهت سند را اعمال می‌کند. آغاز ثابت فارسی و امکان
تلاش مجدد ترجیح زبان بازدیدکننده ایجاد نمی‌کند. فقط پوسته و حالت فشرده در حافظهٔ
مرورگر ماندگار می‌شوند. صفحه‌های کسب‌وکار تنظیمات و تقویم در مرحلهٔ بعد هستند.

فرادادهٔ نامعتبر یا پشتیبانی‌نشدهٔ زبان خطای صریح تنظیمات ایجاد می‌کند و با انتخاب
محلی جایگزین نمی‌شود. نگاشت محلی فقط زبان پشتیبانی‌شدهٔ کتابخانه را انتخاب و نام
تقویم `gregorian` را به `gregory` در Day.js تبدیل می‌کند؛ جهت یا تقویم سرور را
حدس نمی‌زند. [تصمیم‌ها](adr/README.fa.md)، [مالکیت HTTP](http-client.fa.md)،
[چرخهٔ درخواست](request-lifecycle.fa.md)، [قابلیت اطمینان درخواست](admin-request-reliability.fa.md)،
[بومی‌سازی](localization.fa.md) و [سیاست انتشار و بررسی کامل](bootstrap.fa.md) را بخوانید.
