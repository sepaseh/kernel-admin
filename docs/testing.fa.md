# آزمون و بررسی پنل

[English](testing.md) · [فارسی](testing.fa.md)

مرحلهٔ `assistant-guidance` ماژول منتشرشده و محیط جداگانهٔ مؤلفه را می‌آزماید و `applicationReady` همچنان false است. از کوچک‌ترین تست مرتبط شروع کنید و پیش از commit یا تحویل PR با اجازهٔ صریح، [دروازهٔ کامل مرجع](../.agents/validation.json) را اجرا کنید. آماده‌سازی نسخهٔ دقیق در [سیاست اعتبارسنجی](validation.fa.md) آمده است.

تست واحد از Vitest، React Testing Library و پاسخ ساختگی MSW برای ماژول‌های HTTP، چرخهٔ درخواست، ارائه‌دهنده، فرم، ابزارک، کاتالوگ و راه‌انداز زبان و تاریخ استفاده می‌کند. همهٔ ماژول‌های محصول و آستانه‌های موجود در پوشش اندازه‌گیری‌شده حفظ شوند. fixtureها API عملیاتی، نشست واقعی، پایگاه داده یا فایل محیط را به کار نمی‌برند.

تست راهبری Node از فهرست انتشار، مرز منبع، اجراکنندهٔ مرجع و سیاست معنایی CI و scanner حفاظت می‌کند. هماهنگی راهنما و تست ایمنی hook قابل حمل Node در همین مجموعه اجرا می‌شوند. `npm run test:guidance` زیرمجموعهٔ متمرکز است و جای اعتبارسنجی کامل را نمی‌گیرد. موارد اختیاری wrapper پیش از اجرا، Bash قابل استفاده را می‌سنجند؛ نبود پیش‌نیاز میزبان کنارگذاری گزارش می‌شود ولی تست ایمنی قابل حمل الزامی می‌ماند. قالب‌بند اختیاری پس از ویرایش، ورودی را با Node می‌خواند و با CLI محلی ESLint فقط فایل انتخاب‌شده را اصلاح می‌کند؛ تست موقت آن، دست‌نخوردن فایل‌های نامرتبط را هم بررسی می‌کند.

ساخت Storybook و تست Chromium تمام storyهای ثبت‌شده، تعامل واقعی و دسترس‌پذیری را با نقض به‌عنوان خطا می‌پوشانند. مالکان قابلیت و کارخواه مشترک HTTP کاملاً با fixture ساختگی جایگزین می‌شوند؛ درخواست غیرمنتظره حتی اگر مؤلفه آن را بگیرد، شکست ایجاد می‌کند. فرادادهٔ انگلیسی و فارسی نوار ابزار، جهت و پوسته fixture هستند و ترجیح زبان بازدیدکننده نیستند.

دروازهٔ کامل، LCOV واقعی واحد و راهبری را از همان نسخهٔ بررسی‌شده تولید می‌کند. نتیجهٔ مرورگر و دارایی ایستای محیط مؤلفه شاهد جداگانه‌اند. خروجی تولیدشده ثبت نشود. CI میزبانی‌شده، scanner و Sonar بومی head فعلی بررسی مستقل لازم دارند؛ موفقیت محلی شاهد اجرای میزبانی یا تأیید نیست.

مسیر واقعی برنامه، قرارداد واقعی ارائه‌دهنده، اندازه‌گیری bundle تولیدی، مقایسهٔ تصویری فعلی، smoke واقعی Docker و staging یا DAST مستقر همچنان کار آینده‌اند. انتشار سیاست خالص و تصویر تاریخی، آن‌ها را اجرا نمی‌کند. آن‌ها را از تست مؤلفه، منبع منتشرنشده یا بایگانی QA تاریخ‌دار نتیجه نگیرید. هنگام شکست، اولین دستور ناموفق، نسخهٔ دقیق و خطای مشاهده‌شده را ثبت کنید. علت محصول، fixture ساختگی یا پیش‌نیاز میزبان را بدون ضعیف‌کردن assertion یا افزایش آستانه برای پنهان‌کردن خطا تشخیص دهید.

## مجموعه‌های ابزار مقدماتی

چهار مالک واحد موجود، سیاست bundle، سیاست خالص Lighthouse، ورودی production و اعتبارسنجی مقصد workflow را اضافه می‌کنند. سه مالک governance، fixture تولید تنظیمات، بسته‌بندی نسخه و منابع و راهبری Docker را اضافه می‌کنند. آن‌ها یک‌بار در همان فرمان‌های پوشش موجود اجرا می‌شوند؛ مجموعهٔ الزامی سوم یا پروفایل عملیات تازه نداریم. import یا مورد driver ساختگی، Docker، مرورگر، preview یا مقصد بیرونی راه نمی‌اندازد.

assertion خطا و پاک‌سازی، corpus فشار قبلی و مهلت محدود باید الزامی بمانند. گیت فعلی دوازده بررسی الزامی دارد؛ آستانهٔ پوشش محصول و LCOV واقعی واحد و governance تغییر نکرده‌اند. سه نمونهٔ عمومیِ بازبینی‌شده ساختگی‌اند؛ محیط واقعی، گواهی و وضعیت محلی fixture نیستند. [دارایی تاریخی Windows](visual-regression.fa.md) منشأ قدیمی خود را حفظ می‌کند و تأیید فعلی تصویر نیست. [پایداری آزمون](test-reliability.fa.md) را ببینید.
