# آزمون و بررسی پنل

[English](testing.md) · [فارسی](testing.fa.md)

مرحلهٔ application-verification ترکیب برنامهٔ مستقل را می‌پذیرد و همهٔ شرط‌های تست ماژول و محیط مستقل مؤلفه را حفظ می‌کند. از کوچک‌ترین بررسی مرتبط شروع و نسخهٔ دقیق پیشنهادی را با پروفایل الزامی `full` بررسی کنید. [سیاست اعتبارسنجی](validation.fa.md) مالک بررسی محلی و PR، سازگاری کامل و تصویر میزبانی‌شده است؛ انتشار کد محلی به نسخهٔ Windows تصاویر CI وابسته نیست.

تست واحد از Vitest، React Testing Library و پاسخ ساختگی MSW برای ماژول‌های HTTP، چرخهٔ درخواست، ارائه‌دهنده، فرم، ابزارک، کاتالوگ و راه‌انداز زبان و تاریخ استفاده می‌کند. همهٔ ماژول‌های محصول و آستانه‌های موجود در پوشش اندازه‌گیری‌شده حفظ شوند. کمک‌کنندهٔ `dialog-focus` و اجراگر Lighthouse به‌صراحت در LCOV اندازه‌گیری‌شدهٔ واحد قرار دارند. fixtureها API عملیاتی، نشست واقعی، پایگاه داده یا فایل محیط را به کار نمی‌برند.

تست راهبری Node از فهرست انتشار، مرز منبع، اجراکنندهٔ مرجع و سیاست معنایی CI و scanner حفاظت می‌کند. هماهنگی راهنما و تست ایمنی hook قابل حمل Node در همین مجموعه اجرا می‌شوند. فرمان مرجع، فایل‌ها را ترتیبی اجرا می‌کند (`--test-concurrency=1`) تا آزمون‌های فرزندِ وابسته به CPU با فایل‌های دیگر راهبری رقابت نکنند؛ همهٔ ورودی‌ها، assertionها، گزارشگرهای LCOV و مهلت‌های قبلی، از جمله مهلت پنج‌ثانیه‌ای آزمون Markdown، حفظ می‌شوند. `npm run test:guidance` زیرمجموعهٔ متمرکز است و جای اعتبارسنجی کامل را نمی‌گیرد. موارد اختیاری wrapper پیش از اجرا، Bash قابل استفاده را می‌سنجند؛ نبود پیش‌نیاز میزبان کنارگذاری گزارش می‌شود ولی تست ایمنی قابل حمل الزامی می‌ماند. قالب‌بند اختیاری پس از ویرایش، ورودی را با Node می‌خواند و با CLI محلی ESLint فقط فایل انتخاب‌شده را اصلاح می‌کند؛ تست موقت آن، دست‌نخوردن فایل‌های نامرتبط را هم بررسی می‌کند.

ساخت Storybook و تست Chromium تمام storyهای ثبت‌شده، تعامل واقعی و دسترس‌پذیری را با نقض به‌عنوان خطا می‌پوشانند. مالکان قابلیت و کارخواه مشترک HTTP کاملاً با fixture ساختگی جایگزین می‌شوند؛ درخواست غیرمنتظره حتی اگر مؤلفه آن را بگیرد، شکست ایجاد می‌کند. فرادادهٔ انگلیسی و فارسی نوار ابزار، جهت و پوسته fixture هستند و ترجیح زبان بازدیدکننده نیستند.

دروازهٔ کامل، LCOV واقعی واحد و راهبری را از همان نسخهٔ بررسی‌شده تولید می‌کند. نتیجهٔ مرورگر و دارایی ایستای محیط مؤلفه شاهد جداگانه‌اند. خروجی تولیدشده ثبت نشود. CI میزبانی‌شده، scanner و Sonar بومی head فعلی بررسی مستقل لازم دارند؛ موفقیت محلی شاهد اجرای میزبانی یا تأیید نیست.

fixture مرورگر برنامه، مسیرها و احراز هویت و مدیریت را با HTTP ساختگی و نگهبان درخواست غیرمنتظره بررسی می‌کند. Chromium در PR معمول اجرا می‌شود؛ بررسی زمان‌بندی‌شده و درخواست دستی پیش از انتشار، ماتریس کامل را جایگزین همان اجرای Chromium می‌کند. چهار حالت دسترس‌پذیری احراز هویت تست مستقل و محدود دارند و همهٔ ممیزی‌ها و شرط‌های صفحه‌کلید حفظ می‌شوند. Pact از ارائه‌دهندهٔ ساختگی محلی و متعلق به آزمون استفاده می‌کند و API مستقل را تأیید نمی‌کند. نخستین فرمان، نسخه و خطا را ثبت و علت محصول، fixture و میزبان را از هم جدا کنید.

## مجموعه‌های ابزار مقدماتی

چهار مالک واحد موجود، سیاست bundle، سیاست خالص Lighthouse، ورودی production و اعتبارسنجی مقصد workflow را اضافه می‌کنند. سه مالک governance، fixture تولید تنظیمات، بسته‌بندی نسخه و منابع و راهبری Docker را اضافه می‌کنند. آن‌ها یک‌بار در همان فرمان‌های پوشش موجود اجرا می‌شوند؛ مجموعهٔ الزامی سوم یا پروفایل عملیات تازه نداریم. import یا مورد driver ساختگی، Docker، مرورگر، preview یا مقصد بیرونی راه نمی‌اندازد.

شرط‌های شکست و پاک‌سازی، مجموعهٔ ورودی تنش و مهلت محدود حفظ می‌شوند. پروفایل الزامی `full` هفده بررسی دارد؛ تصویر میزبانی‌شده و سازگاری کامل کاربرد جدا دارند و Lighthouse از استثنای زمان‌دار [سیاست کارایی](performance.fa.md) پیروی می‌کند. حد پوشش محصول و LCOV واقعی واحد و governance تغییر نمی‌کنند. فقط نمونهٔ عمومیِ ساختگیِ اعلام‌شده مجاز است؛ محیط واقعی، کلید و وضعیت اپراتور خارج fixture می‌مانند. [قابلیت اطمینان تست](test-reliability.fa.md) را ببینید.

اجراگر تصویر و Lighthouse و ثبت فرادادهٔ ساخت هنگام import همچنان بی‌اثرند. تست چرخه و منشأ با وابستگی تزریق‌شده، برنامه، Chrome یا API راه نمی‌اندازد. آزمون CLI تصویر، مرورگر و driver فرزند ساختگی را تزریق می‌کند تا منشأ تصویر در انتظار، مقادیر محیط ساختگیِ جداشده و پاک‌سازی منابع را بررسی کند؛ این شاهد راهبری است و تصویر واقعی تولید یا تأیید نمی‌کند. فرمان‌های پذیرفته‌شدهٔ برنامه جداگانه preview و مرورگر متعلق به آزمون را با دادهٔ ساختگی اجرا می‌کنند؛ منشأ همسان محیط اجرا، تأیید واقعی انسانی تصویر و ممنوعیت به‌روزرسانی در CI را حفظ کنید. عملیات ارائه‌دهنده، Docker، staging و استقرار مجوز و شاهد مستقل لازم دارند.

fixtureهای فرادادهٔ ساخت و بسته‌بندی انتشار، پیش از ایجاد پوشهٔ متعلق به آزمون، مسیر واقعی پوشهٔ موقت والد را پیدا می‌کنند. آزمون‌های نام جایگزین، مالکیت دقیق خروجی و assertionهای پاک‌سازی را در حالتی حفظ می‌کنند که ویندوز یک پوشه را با نام کوتاه و کامل نشان می‌دهد؛ تفاوت نوشتار مسیر، مجوز خروج از پوشهٔ متعلق به آزمون نیست.

گروه‌های UI و vendor در ساخت production با Vite، ماژول‌های مشترک را بر اساس ورودی‌هایی که واقعاً مصرفشان می‌کنند جدا می‌کنند (`entriesAware: true`). وابستگی مخصوص هر مسیر می‌تواند lazy بماند و صرفاً به دلیل استفاده از یک کتابخانهٔ مشترک وارد گراف بارگیری اولیهٔ احراز هویت نشود. راه‌اندازی Core از import مستقیم provider و hook استفاده می‌کند. یک factory در سطح ماژول با React.lazy، provider آنت‌دیزاین، بازخورد تنظیمات و مسیرها را تنها پس از آماده‌شدن تنظیمات معتبر یا نیاز خطای راه‌اندازی به بازخورد دارای تم، با هم بارگیری می‌کند. نشانگر بارگیری و fallback مربوط به Suspense بیرون این provider می‌مانند؛ مؤلفهٔ نام‌دارِ بارگیری‌شده هویت provider و مسیر را هنگام خطای تازه‌سازی بعدی حفظ می‌کند. محدودیت‌های قبلی اندازهٔ chunk و کل bundle و شرایط کندسازی و آستانه‌های Lighthouse همچنان برقرارند.

تست مسیر، import چیدمان و صفحهٔ عمومیِ منطبق را معلق نگه می‌دارد، شروع موازی هر دو را می‌سنجد و حفظ وضعیت بارگیری دسترس‌پذیر و همان provider نصب‌شدهٔ Ant Design را تا پایان بارگیری بررسی می‌کند. واردکنندهٔ صفحهٔ بدون مجوز، حتی اگر قرار باشد خطا بدهد، نباید فراخوانی شود و تغییر مسیر به داشبورد باید برقرار بماند. صفحهٔ مجاز باید به‌طور عادی import و render شود؛ ردشدن ماژول عمومی یا ماژول محافظت‌شدهٔ مجاز نیز باید به نمایش و گزارش خطای موجود برسد. تمام assertionها و مهلت‌های قبلی مسیر، تلاش مجدد تنظیمات و خطا حفظ می‌شوند؛ این موارد جای گیت کامل مرورگر، تصویر و کارایی را نمی‌گیرند.

موارد تأیید تغییر زبان پیش از کلیک واقعی ماوس، پایان حرکت بازشدن پنجرهٔ فعال را انتظار می‌کشند. trace مرورگر Firefox در Q4 نشان داد کلیک هنگام حرکت ورود به دکمهٔ در حال حرکت نرسید و PUT تنظیمات ارسال نشد. همگام‌سازی آمادگی، assertionهای قبلی تنظیمات، مهلت‌ها و صفر بودن retry را حفظ می‌کند.

پنل احراز هویت، رنگ متن و پس‌زمینهٔ فعال را با هم اعمال می‌کند و این رنگ متن شامل پیوندهای بومی هم می‌شود. اجراهای ناموفق CI و سونار، گزارش‌های ساختگی تولیدشدهٔ مرورگر، مقایسهٔ تصویری و Lighthouse را سه روز نگه می‌دارند.

آزمون خروج، پیش از بازکردن منوی حساب با نگه‌داشتن نشانگر در دسکتاپ یا لمس در دستگاه لمسی، منتظر حذف مانع بارگیری تمام‌صفحه می‌ماند. assertionهای قبلی سربرگ احراز هویت، تغییر مسیر و فرم ورود، مهلت‌ها و صفر بودن retry حفظ می‌شوند.

اجراگرهای Chromium برای E2E برنامه و Lighthouse در ویندوز، [اصلاح سوکت Playwright](https://github.com/microsoft/playwright/pull/43605) را با افزودن `TcpPortRandomizationWin` به فهرست کامل ویژگی‌های غیرفعالِ همان اجراگر اعمال می‌کنند. پیش‌فرض‌های نسخهٔ ثابت 1.64.1 و همهٔ پرچم‌های دیگر حفظ می‌شوند؛ سکوهای دیگر و اجراگر تصویرِ بازبینی‌شده تغییر نمی‌کنند. پس از انتخاب نسخهٔ پایدار دارای اصلاح بالادستی، این سازگاری موقت حذف شود. نسخهٔ مرورگر، ویدئوها، بررسی‌ها، مهلت‌ها، retry و بودجه‌های کارایی تغییر نمی‌کنند.
