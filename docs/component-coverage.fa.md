# پوشش کامپوننت و پیش‌نیازها

[English](component-coverage.md) · [فارسی](component-coverage.fa.md)

برای سیاست و تبدیل خالص، آزمون واحد؛ برای چرخهٔ درخواست و provider، آزمون رگرسیون یکپارچه؛ و برای رفتار قابل مشاهدهٔ فرم، آزمون کامپوننت بنویسید. مرز پاسخ قدیمی، لغو، نسل نشست و مجوز را حفظ کنید. از آزمونی که فقط جزئیات پیاده‌سازی را تکرار می‌کند پرهیز کنید.

کارگاه ایزولهٔ Storybook داستان‌های ثبت‌شدهٔ احراز هویت، حساب، تقویم، تنظیمات، نقش و کاربر، ورودی و layout را با جایگزین کامل و ساختگی API، تعامل واقعی Chromium و audit مسدودکنندهٔ دسترس‌پذیری بررسی می‌کند. برنامهٔ سرهم‌شده یا API واقعی را اجرا نمی‌کند.

پیش‌نیازهای عملیات وارد مجموعه‌های پوشش موجود می‌شوند: سیاست bundle و Lighthouse، ورودی production و اعتبارسنجی مقصد در پوشش واحد؛ تولید تنظیمات، بسته‌بندی نسخه و منابع و راهبری Docker در پوشش governance قرار می‌گیرند. ورودی ساختگی image نمی‌سازد، Chrome یا Docker راه نمی‌اندازد و مقصد مستقر را تأیید نمی‌کند. سیاست خالص Lighthouse وابستگی CLI یا مرورگر ندارد.

[فهرست مرجع](../.agents/validation.json) مالک هر دوازده بررسی الزامی است. دامنهٔ پوشش کد محصول، LCOV واقعی و آستانه‌های موجود را حفظ کنید و مجموعه‌های تازه را به گیت کاملِ الزامی دوم تبدیل نکنید. هنگام توسعه کوچک‌ترین بررسی مرتبط و هنگام تحویل مجاز، گیت کامل روی درخت دقیق را اجرا کنید.

تأیید Pact و provider، E2E کل برنامه، mutation، Lighthouse واقعی و مقایسهٔ تصویری تازه به مرحلهٔ آینده مربوط‌اند. [آزمون](testing.fa.md)، [قرارداد](contract-testing.fa.md) و [سابقهٔ تصویری](visual-regression.fa.md) را ببینید.
