# سیاست اعتبارسنجی مرجع

[English](validation.md) · [فارسی](validation.fa.md)

[فهرست مرجع](../.agents/validation.json) مالک شناسه، فرمان، نوع، پروفایل و مسئولیت CI است. پروفایل الزامی `full` هفده ورودی، شامل E2E برنامه در Chromium، دارد. پروفایل سازگاری کامل، همان اجرای Chromium را با ماتریس چهارپروژه‌ای جایگزین می‌کند و سپس شش تصویر تأییدشده را یک بار بررسی می‌کند. کارایی پروفایل موقتِ گزارش‌دهندهٔ جدا دارد. تنظیمات، `full` را به‌ترتیب بازتاب می‌دهند و بررسی راهنما این بازتاب و مسیریابی منبع را می‌سنجد.

از بررسی متمرکز شروع کنید. پیش از کامیت، push یا تحویل PR با مجوز صریح، درخت دقیق پیشنهادی Git را در پوشهٔ مستقل و تازه صادر و اجرا کنید:

```sh
npm ci
npm run browser:install
npm run validate -- full
```

از نسخهٔ Node ثبت‌شده در [`.nvmrc`](../.nvmrc) و npm همراه آن استفاده کنید. اعتبارسنجی الزامی هر ورودی را یک بار اجرا می‌کند و با نخستین شکست متوقف می‌شود. تعریف ناشناخته، حذف‌شده یا تکراری جای بررسی الزامی را نمی‌گیرد. نبود ممیزی وابستگی شکست است. بررسی کد محلی به نسخهٔ Windows محیط تصاویر بازبینی‌شدهٔ CI وابسته نیست.

| پروفایل       | فرمان                             | مسئولیت                                                                                          |
| ------------- | --------------------------------- | ------------------------------------------------------------------------------------------------ |
| `full`        | `npm run validate -- full`        | هفده ورودی الزامی؛ اعتبارسنجی Chromium در PR معمول و محیط محلی.                                  |
| `complete`    | `npm run validate -- complete`    | شانزده بررسی غیر E2E، یک اجرای کامل چهارپروژه‌ای مرورگر و یک مقایسهٔ تصویر تأییدشده؛ هجده ورودی. |
| `visual`      | `npm run validate -- visual`      | یک مقایسهٔ تصویری مرتبط در محیط CI تأییدشده.                                                     |
| `performance` | `npm run validate -- performance` | یک ممیزی واقعی Lighthouse روی ساخت فعلی تأییدشده، با سیاست موقت گزارش‌دهندهٔ زیر.                |

`npm run browser:install` برای اعتبارسنجی معمول Chromium نصب می‌کند. پیش از بررسی سازگاری کامل، `npm run browser:install:all` را اجرا کنید. Workflow روزانه ساعت 01:30 UTC اجرا می‌شود و انتخاب‌گر `verification` در درخواست دستی برای بررسی منبع پیش از انتشار، به‌طور پیش‌فرض `complete` است. بازاستفادهٔ ساخت موجود فقط پس از تطبیق شاهد منبع و تنظیمات پذیرفته می‌شود؛ ساخت متفاوت یا قدیمی رد می‌شود. شاهد ساخت، فایل‌های عمومی مستقل را هم‌زمان می‌خواند و ترتیب نویسه‌ای نام‌های منبع و پیمایش مرتب پوشه‌ها برای رکوردهای خروجی را حفظ می‌کند. بررسی فایل معمولی و نبود پیوند، همراه با سنجش یکپارچگی منبع و خروجی پیش و پس از عملیات، الزامی می‌ماند. فرمان مستقل `npm run test:lighthouse` همچنان ابتدا منبع فعلی را می‌سازد.

PR معمول Chromium را اجرا می‌کند. بررسی زمان‌بندی‌شده و درخواست دستی پیش از انتشار، ماتریس کامل را به‌جای تکرار ابتدایی Chromium اجرا می‌کند؛ این بررسی منبع است و انتشار عملیاتی نیست. مقایسهٔ تصویری میزبانی‌شده با تغییر ورودی مؤثر بر ظاهر یا درخواست بررسی کامل، یک بار در محیط تأییدشده اجرا می‌شود. تصمیم شامل سورس، دارایی و فونت و سبک و کاتالوگ، تنظیم ساخت و مرورگر، lockfile، fixture و اجراگر و مبناست. نبود اختلاف قابل اتکا، اجرای بررسی را لازم می‌کند. تصویر تأییدشده، منشأ و حدود مقایسه حفظ می‌شوند.

ویرایش صرف عنوان یا توضیح، کار برنامه را تکرار نمی‌کند. تغییر کد یا شاخهٔ مقصد، شاهد بازاستفاده‌شده را نامعتبر می‌کند. CI هویت artifact را به head و مبنا و commit و درخت ادغام و اجرای workflow وصل و درستی گزارش را بررسی می‌کند. کار واقعی با نام **SonarQube Cloud analysis**، LCOV واحد و governance همان اجرا را بدون نصب مرورگر یا اجرای دوبارهٔ مجموعه وارد می‌کند. scanner و دروازهٔ کیفیت غیرهم‌زمان Sonar دو نتیجهٔ الزامی جدا هستند. فراداده، گزارش قدیمی یا کار اجرا‌نشده، موفقیت درخت منبع تازه را ثابت نمی‌کند.

تست واحد `coverage/unit/lcov.info` و تست راهبری Node `coverage/governance/lcov.info` می‌سازد. نتیجهٔ Storybook و مرورگر و مصرف‌کنندهٔ ساختگی شاهد جداست. LCOV ساختگی نسازید و این پوشش منتخب را تأیید ارائه‌دهنده معرفی نکنید. همهٔ شرط‌های محصول، پوشش ۶۹٪ خط، ۶۸٪ دستور، ۵۹٪ تابع و ۵۴٪ شاخه، بودجهٔ حجم، کنتراست، مجوز دسترسی و نگهبان درخواست غیرمنتظره حفظ می‌شوند. موارد اختیاری Bash، نبود پیش‌نیاز را صریح گزارش می‌کنند؛ رگرسیون ایمنی قابل حمل Node الزامی می‌ماند.

هوک اختیاری ایمنی، زیرمجموعهٔ فرمان‌های متنی Bash/sh/dash/zsh را با سقف ۶۵٬۵۳۶ نویسه و حداکثر چهار لایهٔ تو در تو از پوسته یا ابزار واسط مدل می‌کند. بازنویسی تنظیم Git با `-c` فقط برای `color.ui` و مقدارهای متنی `true`، `false`، `auto`، `always` یا `never` پذیرفته می‌شود. کلیدهای دیگر، نام‌ها یا مقداردهی‌های `GIT_CONFIG`/`GIT_CONFIG_*` در دستورهای داخلیِ مدل‌شدهٔ `export`، `declare`، `typeset`، `readonly` و `local`، همچنین `xargs` و عمل‌های اجرایی `find` مسدودند. این ابزار کمکی توسعه، رفتار برنامه‌های دلخواه را مدل نمی‌کند و جای مجوزدهی میزبان را نمی‌گیرد.

Storybook تنظیم مستقل Vite دارد، فایل محیط و کشف متغیر محیطی VITE را غیرفعال می‌کند، API قابلیت‌ها و کارخواه مشترک را کامل جایگزین می‌کند و تعامل و دسترس‌پذیری واقعی Chromium را با خطای متوقف‌کننده می‌سنجد. فایل محیط یا API واقعی لازم نیست. خروجی تولیدشده زیر `coverage` می‌ماند و ثبت نمی‌شود. محدوده و آستانهٔ پوشش محصول را حفظ کنید؛ خروجی مرورگر، LCOV واحد نیست.

Lighthouse همچنان ممیزی واقعی با بودجهٔ معیار و تنظیم کندسازیِ دست‌نخورده است. استثنای موقتِ گزارش‌دهنده در **2026-11-07T00:00:00Z** منقضی می‌شود. **نگه‌دارندهٔ frontend و قابلیت اطمینان تست Kernel Admin** مسئول اصلاح راه‌اندازی fixture و بازنگری پیش از انقضاست. نخستین شکست ممیزی یا آماده‌سازی را جدا گزارش کنید؛ این نتیجه موفقیت نیست. استثنای منقضی تا ثبت تصمیم صریح تازه یا بازگشت الزام متوقف‌کننده، اعتبارسنجی را مسدود می‌کند.

استثناهای دقیق الگوی عمومی فقط `.env.example`، `deploy/docker/.env.example` و `deploy/native/hosts.env.example` با مقدار ساختگیِ بازبینی‌شده‌اند. نسخهٔ خصوصی محلیِ هم‌نام را نخوانید. CLI تولید تنظیمات، بسته‌بندی، سلامت و استقرار ممکن است فایل بنویسد یا به مقصد وصل شود؛ import خالص و fixture ساختگی مجوز عملیات نیست.

ابزار ساخت، تصویر و Lighthouse هنگام import بی‌اثر می‌ماند. تست منابع، fixture موقت و متعلق به خود دارد. تصویر تاریخی، تنظیمات و پروفایل محلی موفق، اجرای میزبانی، بازبینی انسانی، سازگاری ارائه‌دهنده یا استقرار را ثابت نمی‌کند. [آزمون](testing.fa.md)، [منشأ تصویر](visual-regression.fa.md)، [کارایی](performance.fa.md) و [مشارکت](../CONTRIBUTING.fa.md) را بخوانید.

فرمان‌های شواهد، Git را در میزبان‌های ویندوز پشتیبانی‌شده از `C:\Program Files\Git\bin\git.exe` و در میزبان Unix از `/usr/bin/git` اجرا می‌کنند و در `PATH` جست‌وجو نمی‌کنند. نبود فایل اجرایی، بررسی منبع را ناموفق می‌کند. آزمون‌های راهبری با فایل پوشش موقت واقعی و ورودی کنترل‌شدهٔ Git و API و ساعت، استفادهٔ مجدد از تولیدکنندهٔ اصلی و بازگشت به اجرای تازه هنگام نبود، ناقص‌بودن یا نامعتبر بودن سابقه، بارگیری یا گزارش را می‌سنجند. استفادهٔ مجدد به یکسان‌بودن فاز برنامه هم وابسته است. تغییرات پیاپیِ صرفاً عنوان یا توضیحات می‌توانند تولیدکنندهٔ موفق قدیمی‌تر را حفظ کنند، اگر اجراهای موفق جدیدتر پوشش همان تولیدکننده را بدون بارگذاری artifact تازه استفاده کرده باشند؛ جدیدترین اجرای مرتبط همچنان باید با موفقیت کامل شده باشد. تولیدکنندهٔ ناموفق یا ناتمام هرگز منبع پوشش نیست و همهٔ بررسی‌های هویت، فاز، انقضا و گزارش اندازه‌گیری‌شده برقرار می‌مانند. این آزمون‌ها به GitHub وصل نمی‌شوند و محدوده یا آستانهٔ پوشش را تغییر نمی‌دهند.
