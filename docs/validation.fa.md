# سیاست مرجع اعتبارسنجی

[English](validation.md) · [فارسی](validation.fa.md)

[فهرست مرجع](../.agents/validation.json) مالک شناسه، فرمان، نوع، دامنه، job و پروفایل بررسی‌هاست. مرحلهٔ application-verification همهٔ دوازده بررسی قبلی را حفظ می‌کند و هفت بررسی واقعی برنامه می‌افزاید. تنظیمات، نمای مرتب full هستند. شناسهٔ ناشناخته، تعریف تکراری، حذف بررسی الزامی و ورود advisory/manual به full پیش از اجرا خطاست. فهرست کامل مستقل دیگری نسازید.

از کوچک‌ترین بررسی مرتبط آغاز کنید. پیش از هر commit، push یا تحویل PR مجاز، درخت دقیق نهایی پیشنهادی را صادر کنید و با [.nvmrc](../.nvmrc) و npm آن، npm ci، npm run browser:install و npm run validate -- full را اجرا کنید. پروفایل کامل در خطا متوقف می‌شود؛ نبود audit یا پیش‌نیاز مرورگر/محیط خطاست و موفقیت محسوب نمی‌شود. سورس نهایی تغییرکرده را دوباره بررسی کنید و پوشهٔ اصلی آمیخته با فایل منتشرنشده را جای snapshot نگیرید.

آزمون‌های واحد و راهبری، coverage/unit/lcov.info و coverage/governance/lcov.info واقعی را از همان نسخه تولید می‌کنند. حداقل پوشش ۶۹٪ خطوط، ۶۸٪ statement، ۵۹٪ تابع و ۵۴٪ شاخه را حفظ کنید. رگرسیون راهنما و hookهای قابل‌حمل Node یک بار در راهبری اجرا می‌شود؛ نبود پیش‌نیاز اختیاری Bash صریح گزارش می‌شود. برای پنهان‌کردن خطا پوشش، محدودیت زمانی، بودجه یا قواعد دسترس‌پذیری را کاهش ندهید.

Storybook تنظیمات ساختگی جدا و mock کامل API/client را حفظ می‌کند. برنامهٔ پذیرفته‌شده، تحلیل کد بلااستفاده، ساخت production، بودجهٔ bundle، تعاملات مصرف‌کنندهٔ Pact، مرورگر و دسترس‌پذیری واقعی برنامه، مقایسهٔ تصویری مقید به منشأ و Lighthouse را اضافه می‌کند. سازگاری API-provider و عملیات استقرار مستقل‌اند. درخواست غیرمنتظره در همهٔ آزمون‌های مرورگر خطاست؛ بررسی سورس هرگز محیط واقعی یا state اپراتور را بار نمی‌کند.

CI و scanner پیش از فرمان کامل دقیق، بدون شرط و در ریشه، وابستگی و مرورگر نصب می‌کنند. jobهای برنامه پیش‌نیاز Windows منطبق و فرمان واقعی دارند و shell یا نسخهٔ checkout را جایگزین نمی‌کنند. نتیجهٔ واقعی job در head جاری، اجرای scanner، دروازهٔ ناهم‌زمان Sonar و گزارش کامل مسائل حل‌نشده را بررسی کنید؛ پیکربندی اجرا نیست. تغییر حفاظت راه دور مجوز می‌خواهد و پیش از ادغام برنامه، contextهای واقعی build/e2e/visual باید موفق دیده شوند.

خط مبنای تصویری به منشأ محیط و سورس منطبق و بازبینی انسانی واقعی تک‌تک تصاویر تازه نیاز دارد. مقایسهٔ موفق با capture تأییدنشده کافی نیست. دادهٔ تاریخی، تاریخی می‌ماند. از نتیجهٔ محلی برنامه، استقرار production، تأیید provider، DAST، mutation یا workflowهای مستقل عملیات نتیجه نگیرید.
