# آماده‌سازی بررسی مقصد دارای مجوز

[English](staging.md) · [فارسی](staging.fa.md)

[اعتبارسنج‌های مقصد](../scripts/validate-workflow-targets.mjs) و آزمون‌های ساختگی، پیش‌نیازهای منتشرشده‌اند. تطابق صریح میزبان، URL بدون اطلاعات ورود و برای ورودی smoke، تطابق شناسهٔ تغییرناپذیر با نسخهٔ مورد انتظار را می‌سنجند. اعتبارسنج DAST میزبان production پیکربندی‌شده را نیز رد می‌کند. این بررسی‌ها فقط مقادیر داده‌شده را می‌خوانند؛ مجوز درخواست، ایمنی DNS و redirect یا وجود سرویس مستقر را اثبات نمی‌کنند.

workflow و مجموعه‌آزمون مرورگریِ staging، smoke و DAST به مرحلهٔ آینده موکول شده‌اند. در این مرحله چنین jobی نصب یا اجرا نشده و نتیجهٔ موفقی برای آن اعلام نمی‌شود. برنامهٔ فعلی هنوز سرهم‌بندی نشده است؛ آزمون مقصد واقعی باید تا فعال‌سازی و مجوز صریح برای همان مقصد و عملیات صبر کند.

برای عملیات آینده، میزبان‌های مجاز برنامه و API، URL سلامت، شناسهٔ نسخه، دامنهٔ مجاز، روش نگهداری اطلاعات ورود و برنامهٔ پاک‌سازی و نگهداری شاهد را ثبت کنید. پیش از هر فعالیت شبکه، همین مقادیر صریح را اعتبارسنجی کنید. نمونهٔ عمومی مجوز نیست و نباید مقصد را با خواندن وضعیت اپراتور کشف کرد. آزمون ساختگی باید از production مستقل بماند.

پس از پیاده‌سازی، revision واقعی workflow، دامنهٔ مقصد، اولین خطا و نتیجهٔ مشاهده‌شده را ثبت کنید. موفقیت اعتبارسنج محلی یا وجود متغیر تنظیمات مخزن، اجرای کامل staging نیست.

[استقرار](deployment.fa.md)، [امنیت](../SECURITY.fa.md) و [پایداری آزمون](test-reliability.fa.md) را بخوانید.
