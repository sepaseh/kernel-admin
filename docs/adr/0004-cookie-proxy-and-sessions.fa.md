# ADR 0004: نشست API و پراکسی کوکی سایت

[English](0004-cookie-proxy-and-sessions.md) · [فارسی](0004-cookie-proxy-and-sessions.fa.md)

تاریخ: ۲۳ اکتبر ۲۰۲۶. وضعیت: پذیرفته‌شده.

به‌روزرسانی محدوده: ۲۷ اکتبر ۲۰۲۶. انتشار غیرقابل اجرای `core-auth` مقدار
`applicationReady: false` دارد. این سند مالکیت مصرف‌کننده و رفتار لازم برای
یکپارچه‌سازی را حفظ می‌کند. پیاده‌سازی API و وب‌سایت، استقرار کوکی، ابطال نشست،
ارسال OTP یا امنیت تولید را تازه بررسی نمی‌کند.

## زمینه و تصمیم

API مالک اعتبارنامه، ماندگاری نشست، اجرای احراز هویت و مجوزدهی است. کلاینت Axios
منتشرشدهٔ پنل bearer را در حافظه نگه می‌دارد و درخواست جداگانهٔ refresh مبتنی بر
کوکی را هماهنگ می‌کند. پاسخ توکن در زمان اجرا اعتبارسنجی می‌شود؛ نسل درخواست و
ورود مانع تغییر ورود تازه توسط پاسخ، refresh یا خروج قدیمی است. signal اختیاری
احراز هویت این محافظ را حفظ می‌کند و پیش از ثبت توکن ورود و ثبت‌نام بررسی می‌شود.

وب‌سایت مستقل مالک مصرف‌کنندهٔ کوکی و پراکسی خود است. پراکسی هم‌مبدأ auth و account
با کوکی HttpOnly باید مسیرهای محدودِ مجاز داشته باشد، هدر اصلی Set-Cookie را حفظ
کند، Origin بیگانهٔ تغییر را رد کند، فیلد توکن را از پاسخ موفق JSON سایت بردارد و
از cache پاسخ خصوصی جلوگیری کند. این‌ها الزامات بررسی جداگانهٔ مالکان وب‌سایت
هستند و قابلیت عرضه‌شده یا آزموده‌شدهٔ این نسخهٔ پنل نیستند. هیچ مصرف‌کننده مالک
hash گذرواژه یا مجوزدهی پایگاه داده نیست.

## پیامدها

پنل به مبدأ API معتبر و دفاع XSS نیاز دارد؛ نگهداری bearer در حافظه به‌تنهایی
هیچ‌کدام را فراهم نمی‌کند. رفتار refresh چرخش توکن یا تشخیص استفادهٔ مجدد در سرور
را ثابت نمی‌کند. شکست نهایی کلاینت اعتبارنامهٔ محلی را پاک می‌کند و نشست سرور را
باطل نمی‌کند. لغو نمی‌تواند تغییر ثبت‌شدهٔ سرور یا اثر کوکی مرورگر را برگرداند.

شکل نشست، انقضا، خروج صریح و ابطال پس از تغییر یا بازیابی گذرواژه را با مالکان API
بررسی کنید. رفتار کوکی، وضعیت و خطا را با مالکان وب‌سایت بررسی کنید. پیش از آماده
دانستن مسیر وابسته به OTP، ارسال production و کنترل سوءاستفاده شاهد جداگانه لازم
دارد. یافته‌های قدیمی این حوزه‌ها زمینهٔ تاریخی هستند و نتیجهٔ تازهٔ موفق یا
ناموفق مخزن‌های مستقل نیستند.
